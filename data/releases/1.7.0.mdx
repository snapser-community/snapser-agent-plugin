# 1.7.0
##### March 23, 2026

## Breaking Changes
1. Scheduler Snap – Internal API Calls
Previously, the Scheduler Snap had a bug that prevented selecting internal API calls. This has now been fixed. If you were using API-key–based APIs as a workaround, you should migrate those workflows to use internal API calls instead.

2. Guilds.RemoveMember Path Parameter Update
We’re updating the Guilds.RemoveMember endpoint to correctly reflect the resource being modified.
```
Old: /v1/guilds/{guild_id}/members/{user_id}
New: /v1/guilds/{guild_id}/members/{target_user_id}
```
Older SDKs were incorrectly sending the admin’s user_id when calling RemoveMember. With this release, those incorrect calls will begin failing.

## Snapctl
1. Snapctl now supports build-kit secrets injection. You can now pass secrets as environment variables or add secrets via a file using the new `--secrets` variable.
```
--secrets "id=token_from_env,env=token_from_env|id=token_from_file,src=/tmp/test_secret.txt"
```
Then inside your Dockerfile you can utilize those secrets
```
# Example if you want to use Build-kit secrets
# Run this in your terminal
# $ export token_from_env="my-env-secret-123"
# $ echo "my-file-secret-456" > /tmp/test_secret.txt
# Then uncomment the following lines to use the secrets in the Dockerfile

RUN --mount=type=secret,id=token_from_env \
  --mount=type=secret,id=token_from_file \
  echo "Env secret:" && cat /run/secrets/token_from_env && \
  echo "File secret:" && cat /run/secrets/token_from_file
```
2. You can now set your application Id via an environment variable `SNAPSER_APPLICATION_ID` or by adding it in your snapser config file. You do not have to explicitly pass the `--application-id` for commands like: enumerate, create, clone
