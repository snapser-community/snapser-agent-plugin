# 1.11.0
##### June 23, 2026

## Breaking Changes
1. **Analytics Query Tool removed** — the standalone Query Tool has been retired. Use the new `Launch SQL Lab` button (previously `Launch BI`) to run ad-hoc analytics queries.
2. The Snapser Documentation is no longer embedded in the Portal. All documentation links now point to the new docs app.

## Spotlight
1. **Snapend Secrets** — first-class secrets management for BYOSnaps. Upload any number of secrets via snapctl, tag them, and mount them into BYOSnaps through the BYOSnap profile. Cluster manifest, snapctl, Portal, and the WebApp have all been wired up end-to-end to support secrets.
2. **User Reporting** — a brand new tool for in-game player to user reporting. View and act on reports from a new User Reporting tool.
3. **GDScript Godot SDK** — Snapser now ships a GDScript SDK for Godot.
4. **Next.js 16 client upgrade** — the Snapser WebApp has been upgraded to Next.js 16 for performance, security, and modern React features.

## Snapctl

### Important changes
1. You can now add secrets and attach them to your BYOSnaps.
2. Snapend SDK download now supports the Godot GDScript SDK.
3. New command: `snapctl byosnap next-version --byosnap-id <id>` shows the next versions you can publish — patch, minor, and major — based on your highest published version, so you don't have to guess which version your next `publish` will accept.

### Commands
#### Byosnap
1. `snapctl byosnap publish` now validates your version up front. The `--version` you pass must be strictly greater than the highest already-published version (e.g. if `v1.0.1` is your latest, you must publish `v1.0.2` or higher). If it isn't, the command fails immediately — before building or pushing any image — instead of pushing first and erroring later. Brand-new BYOSnaps with no versions yet can use any valid `vX.Y.Z`.
2. `snapctl byosnap sync` now confirms the version exists before doing any work. Since `sync` only updates an already-published version, an unpublished `--version` now fails fast with a clear, actionable message (pointing you to `publish` or `direct-deploy`) instead of building/pushing an image and then failing with a misleading "BYOSnap not found." error. Failed syncs no longer leave orphaned image tags in your registry.
