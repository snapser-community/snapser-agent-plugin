# Tool Builder
Snapser has built a tool allowing you to build your own custom configuration tool for your BYOSnap. With this tool, you do not have to write your own HTML, CSS, and JS to build a configuration tool. You use the Tool Builder to create a custom form that will be rendered in the Snap Configuration view for your BYOSnap. This tool does not work with the Snapser User Manager view.

<Warning>
  As of December 2025, Snapser supports HTML/JS/CSS based tools for both BYOSnap configuration and User manager. The Tool Builder is an additional way to create configuration tools only without writing code. Note, it has some limitations in terms of the components and the layout you can create. We highly recommend you consider using the HTML/JS/CSS tool route.
</Warning>

## Concept
The Tool Builder is a form selector tool that allows you to create a custom configuration tool for your BYOSnap. Once you are happy with the UI, you can save the form as a tool JSON file. This JSON file can then be uploaded as part of your BYOSnap `snapctl byosnap publish` or `snapctl byosnap direct-deploy` commands.

When Snapser detects the uploaded tool file for a particular version of your BYOSnap, it will first display all the tools you have uploaded for that version. You can then select the tool you want to use for the Snap Configuration view. This will now take you to a view that renders the form you created in the Tool Builder. Additionally, it will also allow you to save the configuration.

![BYOSnap Profile Tool](/images/docs/byosnap-config-tool-builder.png)

## BYOSnap Setup

You will need to make sure your BYOSnap is equipped to handle configuration settings. This is done by adding a **Settings Endpoint** in your BYOSnap code that should support both **GET** and **PUT**.

<Note>
  The port used by the tool is the one your provided in the ingress.external.port field in your BYOSnap profile. Check the BYOSnap [documentation](/docs/custom/bring-your-own-snap#byosnap-ingress-ports) for more information.
</Note>

Snapser first hits the **GET** endpoint to get the configuration settings. It then renders the form you created in the Tool Builder. Once you hit save, Snapser will hit the **PUT** endpoint to save the configuration.

<Note>
You are then expected to use the Snapser **Storage** snap or your custom Database to store the configuration.
</Note>

In the Python example below:
1. `$prefix` is `/v1`
2. `$byoSnapId` is `byosnap-jinks-flask`
3. `/settings` is always appended to the path.
3. `$endpoint` is what you added in the tool builder, in this case, `/analytics-single`.

```python

  # Query parameters

  environment = request.args.get(
    'environment', default=os.environ.get('SNAPEND_ENVIRONMENT'))
  # JSON payload which is the payload you see in the example above
  data = request.get_json()
```

## Tool Configuration
### Tool Admin
1. **Tool Id**: This is the unique identifier for the tool. It should be unique across all tools. Only
    alphanumeric characters and hyphens are allowed.
2. **Endpoint Path**: This is the path that Snapser will hit to get and save the configuration. It is
    appended to the **/$prefix/$byoSnapId/settings** path.

### Environment Support
When creating a custom form you have two options.
- **Single**: This is a single form that is rendered for all environments.
- **Multi**: This is a form that is allows you to enter configuration for dev, stage and prod environments in a single go.
    With this form type, Snapser will automatically pick the right configuration for the environment,
    when you are cloning or promoting your Snapend.

### Payload
This is a view only section that shows you the JSON payload that will be sent to your BYOSnap when you hit save in the configuration tool.

### Download
Clicking the download button allows you to download the tool JSON file. Note that this file needs to either be at the root of your BYOSnap code, or at the provided `--resources-path` path when you publish your BYOSnap.

<Note>
  You will not be able to download the tool JSON file if you have not provided a Tool Id.
</Note>

![Configuration Builder](/images/docs/tutorials/byosnap-advanced-config-tool.png)

### Main
This is the start of your custom tool building. Here you can add the following components:
1. **Title**: The title of the form.
2. **Description**: A description of the form.

### Sections
You can add multiple sections to your form. Each section needs to have:
1. **Id**: A unique Id for the section.
2. **Title**: The title of the section.
3. **Subtitle**: An optional subtitle for the section.
4. **Helper Text**: An optional helper text for the section.

![Configuration Builder](/images/docs/tutorials/byosnap-advanced-config-tool-section.png)

### Components
Once you add a section, you can start adding components to the section. You can add the following components:
1. **Text**: This is a text input field.
2. **Number**: This is a number input field.
3. **Select**: This is a dropdown field.
4. **Multi-Select**: This is a multi-select dropdown field.
5. **Checkbox**: This is a checkbox field.
6. **Radio**: This is a radio button field.
7. **Group**: A group of three components from above with an optional, delete icon per row and an optional button allowing users to add more rows.

<Note>
  Each component takes the appropriate fields for the setup, like label, placeholder, options etc.
</Note>
