# Bring your Own Workstation

Bring your own Workstation and attach it to your Snapend. This effectively allows you to run your code locally and debug it.

## Concept

With Snapser’s Bring Your Own Snap (BYOSnap) technology, you can bring your own server code — written in any language — and attach it to your backend as a Snap. This enables you to run your own microservices, macroservices, or even full monoliths. To make development even smoother, Snapser’s CLI tool, snapctl, also supports Bring Your Own Workstation (BYOWS). BYOWS lets you attach your local workstation, exposing your locally running BYOSnap code directly to your Snapend. This allows you to run and debug your code locally, as if it were part of the live backend.

![BYOWs](/images/docs/tutorials/byosnap-byows.png)

<Warning>
  BYOWS only works for Development Snapends. You cannot attach your workstation to a Staging or a Production Snapend.
</Warning>

## Pre-requisites

### 1. Python 3.X and Pip
The Snapser CLI tool that you will use for BYOSnaps, has a dependency on Python 3.X and Pip.
MacOS comes pre installed with Python. But please make sure you are running Python 3.X.
On Windows, you can download Python 3.X from the Windows store.

### 2. Docker
Some of the commands also need docker. You can download the latest version of Docker from the
[Docker website](https://www.docker.com/products/docker-desktop).

<Note>
  **IMPORTANT**: Open up Docker desktop and settings. Make sure this setting is **disabled**
  **Use containerd for pulling and storing images**.
  ![Docker Issue Pic](/images/docs/docker-setting.png)
  This is because Snapser uses Docker
  to build and push images to the Snapser registry. Having this setting enabled will
  cause issues with the Snapser CLI tool.
</Note>

### 3. Snapser CLI

Snapser requires customers to use the Snapser CLI tool to build, upload and
push images to the Snapser registry. The The [Snapctl tool](https://pypi.org/project/snapctl/) is available on Pypi and
can be installed via pip. The CLI tool supports both MacOSX and Windows OS.

Detailed documentation on the Snapser CLI tool can be found [here](/docs/resources/cli).

</CodeGroup>

#### Snapser CLI Setup

##### Get your Snapser Access Key

<Note>

  - **game-admin**

Create a file named `~/.snapser/config`. Open it using the editor of your choice and replace with your
personal Snapser Access key. Save the file.

## Usage
### 1. Attaching your BYOSnap
- Make sure you have a Snapend with your initial BYOSnap code running on Snapser.
- Then, run the following command to attach your BYOSnap code to your Snapend.
```bash
# $snapend_id = Your Snapend ID
# $byosnap_id = Your BYOSnap ID
# $http_port = The port on which your BYOSnap code is running locally
snapctl byows attach --snapend-id $snapendId --byosnap-id $byosnapId --http-port $serverPort
 ____

|____/|_| |_|\__,_| .__/|___/\___|_|
                  |_|

Info Trying to extract API KEY from /Users/Aj/.snapser/config:profile playtest_ajco"
Info Forwarding https://gateway-accel.snapser.com/k11voxwz/v1/byosnap-inter -> http://localhost:5003/*

    source /Users/Aj/.snapser/byows_env_setup.sh

```
- This will ensure that any calls that are made to your Snapend BYOSnap will be routed to your local BYOSnap code instead.
- **IMPORTANT**: If you are accessing other Snaps from your BYOSnap either directly or using the Internal SDK, you should follow the steps below to set up the environment variables.

#### Supporting the Internal SDK
- When you run the `snapctl byows` command, you will get a file called `byows_env_setup.sh` for MacOSX or `byows_env_setup.ps1` for Windows stored in the `~/.snapser/` directory. This file contains the environment variables that the BYOWS technology will beed to route internal calls to the appropriate Snaps.
  <Note>
    BYOWS smartly, will route both Internal and GRPC calls to the appropriate Snaps. Just make sure you have the environment variables set up correctly.
  </Note>
- To setup, the environment variables, run the following command in a different tab to set up the environment variables for your BYOSnap code.
```bash
# MacOSX
source ~/.snapser/byows_env_setup.sh
# Windows
.\.snapser\byows_env_setup.ps1
```
- You should then start the BYOSnap local server in the same tab that has the environment variables set up. This will ensure that the BYOSnap code can access the internal SDK and other Snaps in your Snapend.

<Warning>
  **IMPORTANT**: At the moment, only one workstation from a single physical user can be attached to a Snapend. Meaning, if you as a dev have two BYOSnaps on your workstation, you can only attach one of them to a Snapend. If you try to attach the second one, it will fail with an error.
</Warning>

### 2. Reset BYOWS
If you want to reset the BYOWS connection, you can run the following command:
```bash
# $snapend_id = Your Snapend ID
snapctl byows reset --snapend-id $snapendId
```
This will remove the BYOWS connection and stop forwarding requests to your local BYOSnap code.

<Note>
  It should be noted that terminating the BYOWS attach via Ctrl-C or any other signal does clean up the BYOWS connection. However, this command can always be used to force reset the connection.
</Note>

## Networking
When you run the above command, Snapser creates a secure tunnel between your workstation and your Snapend using Snapser's internal networking.
Here's what happens:

1. External calls to your Snapend BYOSnap are routed to your local BYOSnap code instead.
    - **Example**: A request to https://gateway-accel.snapser.com/wsxo1j1c/v1/byosnap-basic/* will be routed to your local server running on the port you specified with the --http-port argument.
1. Internal calls from your local BYOSnap to other Snaps in your Snapend are automatically handled.
    - Inside your local code, when you call another Snap, you are expected to use the internal SDK and environment variable overrides. Thanks to the BYOWS environment setup, these calls will correctly route to the live Snaps in your Snapend — without any code changes.
