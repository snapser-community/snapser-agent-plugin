# Snapend Configuration Sync

A live app or game runs on a lot of configuration: storage blob names, authentication connectors, in-app purchase secrets, and more. With a live cadence, experiment, segment, and analytics configurations also change often.

Keeping all of this in sync across environments is hard. The Sync Configuration tool copies snap configuration from another Snapend in the same app into the Snapend you are on.

<Warning>
  This tool is only available for Premium tier customers.
</Warning>

## Tool Location

Open the Snapend you want to sync **into**, then go to **Tools** → **Sync Configuration**.

![Snapend Pic](/images/docs/snapend-sync-tool.png)

<Note>
  The tool needs a desktop browser, and is unavailable while the Snapend is updating or in a failed state.
</Note>

## Who can sync

You need two kinds of access: edit access on the Snapend you sync into, and view access on the snaps you sync from.

| Where | Role you need |
|---|---|
| **Destination** — the Snapend you are on | **cluster-edit** or higher, or a game or company role that covers it |
| **Source** — every snap | **cluster-view** or higher on the source Snapend, or a game or company role that covers it |
| **Source** — individual snaps | A **cluster-service-** role on that snap |

The **Select Source Snapend** list shows every Snapend in the app where you hold any role. After you pick one:

- With **cluster-view** or higher on it, every snap is loaded.
- With only **cluster-service-** roles, just those snaps are loaded. The other snaps are listed as **No view access** and cannot be synced.

For example, say you are **cluster-admin** on Snapend A and **cluster-view** on Snapend B. You can sync every snap from B into A. If you also have **cluster-service-view** on just the Auth snap of Snapend C, you can sync only Auth from C into A.

See [Access](/docs/resources/portal/access) for what each role allows.

## Sync Algorithm

A sync is a full replace. The configuration from the source Snapend replaces the configuration in the destination Snapend.

There is one exception. Some settings, like Auth and IAP connectors, are multi-environment aware, so the same connector can be used in several environments. For these, the tool takes the environment of the source and destination Snapends into account.

![Snapend Pic](/images/docs/snapend-sync-final-config.png)

### Selective Snaps

You choose which snaps to copy from the source Snapend. Use the toggle next to each snap, or **All** to toggle every snap you can sync. Only snaps that are toggled on are copied.

Each snap row shows its state:

| State | Meaning |
|---|---|
| Toggle | The snap can be synced. |
| **Snap not present** | The snap is not on the destination Snapend, so there is nothing to sync into. |
| Warning icon with **View Logs** | The source configuration failed validation on the destination. Hover the icon for the reason, or open **View Logs** to see the snap's validation logs. |
| **No view access** | You do not have view access to this snap on the source Snapend. |

## Manual Configuration
You can also edit a snap's configuration by hand before syncing. Click **Diff** to see the current and new configuration side by side.

![Snapend Pic](/images/docs/snapend-sync-auth-edit.png)

Edit the new configuration, then click **Validate & Save**. The tool validates your edit against the destination Snapend before you sync.

![Snapend Pic](/images/docs/snapend-sync-auth-edit-done.png)

When you are ready, click **Sync** and confirm.

### Limitations

#### Full replace only
You can only copy a snap's whole configuration. For example, if Snapend A has 3 experiments and Snapend B has 2, you can copy all 3 experiments from A to B, or none. You cannot copy just 2 of them.

#### No user data copy
Only snap configuration is copied, never user data. User data stays isolated between environments.
