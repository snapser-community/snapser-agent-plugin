# Infrastructure as Code
Snapser supports Infrastructure as Code (IaC) for your Snapend. Every Snapend created on Snapser and then the snap specific configuration is all stored as a Snapend Manifest. The Snapend Manifest is a file that describes the desired state of your Snapend.

<Warning>
  The Snapser Snapend manifest file is a human readable file that describes the current state of your Snapend. It it Snapser's own version of the Infrastructure as Code and is not a terraform, cloudformation or a Kubernetes manifest.
</Warning>

## Snapend Manifest
Manifest is a JSON or a YAML file that represents the present state of your Snapend. This includes the infrastructure, snaps, and their configurations. Developers can download this manifest and store it in their source control. This allows them to version control their Snapend configuration.

Here is an example of a Snapend Manifest that includes two snaps, `analytics` and `auth`. As you can see, each snap has its own configuration and settings. It should be notes, that some Snaps allow you to configure different settings for different environments like `dev`, `prod`, and `stage`. These configurations are also a part of the Snapend Manifest.

## BYOSnaps in the manifest

If your Snapend runs any BYOSnaps, the manifest carries each one's deployment
configuration — CPU, memory, replica counts, command, args, env vars, the HPA
block, and any [Secrets Manager](/docs/custom/tools/secrets-manager) references
it mounts.

**The manifest is the source of truth for all of that.** It is what the deploy
reads, and it is the only place a change to a running BYOSnap can come from.

<Warning>
  A BYOSnap's `snapser-byosnap-profile.json` seeds this manifest exactly once — at
  the moment the BYOSnap is added to the Snapend. From then on the manifest owns
  the configuration. Publishing an edited profile updates the BYOSnap's stored
  template for future attaches, but does not change this manifest, and neither does
  bumping the BYOSnap to a newer version. See
  [Profile vs. Snapend Manifest](/docs/custom/bring-your-own-snap#profile-vs-snapend-manifest).
</Warning>

So there are exactly two ways to change what a BYOSnap runs with on a given
Snapend:

1. **Snapend → Customize Snapend** in the portal, then deploy.
2. Download the manifest, edit it, and apply it — the CI-friendly path:

<CodeGroup title="Editing a BYOSnap's config via the manifest" tag="bash">
```bash
# 1. Always download fresh - applying a stale manifest will be rejected.
snapctl snapend download --snapend-id $snapend_id --category snapend-manifest --format json --out-path .

# 2. Edit the BYOSnap's block in the downloaded manifest.

# 3. Apply it back.
snapctl snapend apply --manifest-path-filename ./snapser-$snapend_id-manifest.json --blocking
```
</CodeGroup>

<Note>
  To confirm what is live without reading JSON, open **Snapend → Infrastructure →
  Dashboard**. It renders straight from this manifest and shows each BYOSnap's
  CPU, memory, HPA state and its attached secrets, args and env vars.
</Note>

## Downloading a Snapend Manifest
To download your Snapend manifest, first go to your Snapend home page. Then, you go to the
Snapend > Tools > Downloads tool. Here you will see a widget called **Manifest** that allows you to download
the manifest.
There are two formats available for the manifest: JSON and YAML. You can select the format you want to download.


## User Data
It should be noted that a Snapend manifest does not contain any user data. This means, if you download
a manifest and then upload it to a different Snapend, the user data will not be transferred. But the new
Snapend will be a replica of the old Snapend in terms of infrastructure, snaps and the configuration.

## Snapser CLI
Snapser provides a CLI tool that allows you to download, clone and apply a Snapend Manifest.

### Downloading a Snapend Manifest
To download a Snapend Manifest, you can use the following command:

<CodeGroup title="Download Manifest">
```bash
# Download a Snapend Manifest
# snapend_id: The id of the Snapend you want to download the manifest for
# format: The format of the manifest, can be either json or yaml
# out_path: The path where you want to save the manifest
snapctl snapend download --snapend-id $snapend_id --category snapend-manifest --format $format --out-path $out_path
```
</CodeGroup>

### Clone a Snapend using a Manifest
To clone a Snapend using a manifest, you can use the following command:
<CodeGroup title="Clone a Snapend via a Manifest">
```bash
# Clone a Snapend from a manifest
# game_id: The id of the Game or App; you can get this from the App home page
# name: Any name for your Snapend. Should be alphanumeric and less than 50 characters and no spaces
# env: This should be either development or staging
# manifest_path_filename: The path to the manifest file. Including the file name
# blocking (optional): If you want the command to block until the Snapend is created
snapctl snapend clone --game-id $game_id --name $name --env $env --manifest-path-filename $manifest_path_filename --blocking
```
</CodeGroup>

### Applying a Snapend Manifest
To apply a Snapend Manifest, you can use the following command.

<Note>
You should have the latest manifest before applying changes. This is to prevent a user stomping over
someone elses changes.
</Note>

<CodeGroup title="Apply updates to a Snapend via a Manifest">
```bash
# Apply updates to a Snapend via a manifest
# manifest_path_filename: The path to the manifest file. Including the file name
# blocking (optional): If you want the command to block until the Snapend is created
snapctl snapend apply --manifest-path-filename $manifest_path_filename --blocking
```
</CodeGroup>
