# Roblox Experience
This guide will help you set up a Roblox experience with Snapser. This is a simple experience, that uses Snapser’s authentication, profiles, storage, statistics and leaderboard snaps. You can use this example to understand how to integrate Snapser into your own Roblox project.

## Step 1: Set up your game

To integrate Snapser features into your game, you need to create an account and add your game to it. This section demonstrates how to do that.

<Note>
  If you have already created a game in Snapser, you can skip this step and proceed to the next one.
</Note>

1. **Log in to your Snapser account** at https://snapser.com/login.
2. Navigate to the **Apps dashboard** and click on the **New Game** button located in the upper right corner.
3. **Enter the name of your game** in the designated field. It's advisable to use a name that closely matches your game's title to avoid confusion among your team members. Click **Add** when done.
    ![Add new game name](/images/docs/tutorials/create-snapend-add-game.png)
    <Note>
    Avoid adding prefixes like "dev", "staging", or "prod". Snapser supports multiple environments for each game, allowing you to create a separate custom backend for each stage of your game development.
    </Note>

<Checkpoint step={1}>
  Shortly after, your game will appear in the Apps dashboard, ready for you to build your first custom backend.
</Checkpoint>


## Step 2: Create a Snapend

1. In the **Apps dashboard**, click on the game you have added. This action brings up a view that shows the development, staging, and production environments. Since there are currently no Snapends, let's add one.
![GameClick](/images/docs/tutorials/create-snapend-game.png)
1. In the Development environment, click on **Create a Snapend**.
![GameClick](/images/docs/tutorials/create-snapend-game-home.png)
1. **Enter the name of your Snapend** in the **Name your Snapend** field and click **Continue**.
    ![Name your Snapend](/images/docs/quick-start/name-your-snapend.png)
1. On the next page, select the following snaps:
   1. Authentication
   2. Leaderboard
   3. Profiles
   4. Statistics and segmentation
   5. Storage
    ![Cluster](/images/docs/tutorials/unity-sp-snapend.png)
1. Keep clicking **Continue** and then on the Review page click the **Snap It** button. A pop-up window will appear showing you the state of creating your cluster, which takes a moment or two to complete.
1. As Snapser finishes setting up the Snapser cluster in Kubernetes (which includes infrastructure, configuration of Snaps, network and security, and generating your Snapend), click the **App** button to wait for your Snapend to be operational.
1. Once the Snapend is ready, you will see a green dot mark on the Snapend widget. This indicates that your Snapend is ready to use.
![Snap Dashboard](/images/docs/tutorials/create-snapend-cluster-ready.png)
1. Click on the Snapend widget to go to the Snapend dashboard.
![Snapend Dashboard](/images/docs/tutorials/unity-sp-snapend-dashboard.png)
1. **IMPORTANT**: On this page, copy the **Snapend ID**. You will need to replace this in the Roblox codebase.

## Step 3: Configure Snaps
On your Snapend homepage look for Quick links. Click the **Snaps Configuration** button under **Quick Links** to go to the Snaps configuration home page. Now, lets configure the Snaps one by one.

### A. Authentication Configuration
<Note>
    In our Roblox experience, we want the user to start playing the game without any login friction. This is why we are going to add the anonymous connector. To add the anonymous connector, please follow the instructions below.
</Note>

1. Click on the **Authentication** widget to open the Auth snaps configuration page.
1. Select the `Authentication > Connectors` tool from the tool navigation and then click on the **Add a connector** button. You will see quite a few connectors in the menu but lets select **Anonymous** and press Save.
![Add Anonymous Authentication](/images/docs/tutorials/snapend-create-admin-auth-anon.png)
1. Then click the back button to go back to the configuration home page.


### B. Leaderboard Configuration
<Note>
    In our Roblox experience, we are going to track the max_distance anyone playing the game has traveled. Additionally, we also want to see the distance each player has traveled in total. This is so users playing the game can see how they are doing compared to other players. To add the leaderboards, please follow the instructions below.
</Note>
1. Click on the **Leaderboards** widget to open the Leaderboards snaps configuration page.
1. Here we are going to create two leaderboards:
    - max_distance
    - distance_traveled
1. To create a leaderboard, click on the `Leaderboards` tool from the tool navigation and click on the **+ Leaderboard** button. This will open up a form, where you can add the new leaderboard details. Add the following leaderboards and click save.
   1. `Name` - `max_distance`
   1. `Description` - `Max distance traveled by the player`
   1. `Period - Start time` - Use the date picker to select the current date time, such that the leaderboard is active.
1. Keep the default values for the rest of the fields. Repeat the same for the second leaderboard with the following values:
    1. `Name` - `distance_traveled`
    1. `Description` - `Total distance traveled by the player`
    1. `Period - Start time` - Use the date picker to select the current date time, such that the leaderboard is active.
![Leaderboard Config](/images/docs/tutorials/unity-sp-leaderboard.png)
1. Then click the back button to go back to the configuration home page.

### C. Profiles Configuration
<Note>
    We want to allow, players to chose their own profile attributes like a gamertag. To add a profile attribute, please follow the instructions below.
</Note>
1. Click on the **Profiles** widget to open the Profiles snaps configuration page.
1. Select the `Attributes` tool from the tool navigation and then click on the **Profile Attribute** button. This will open up a form, where you can add the new attribute details. Add the following attributes and click save.
   1. `Name` - `gamertag`
   2. `Category` - `Unique`
   3. `Type` - `text`
1. Keep the default values for the rest of the fields. You can add more attributes if you want to but for this demo we will keep it simple.
    ![Profile Config](/images/docs/tutorials/unity-sp-profile.png)
1. Then click the back button to go back to the configuration home page.

### D. Statistics Configuration
<Note>
    We want to track the distance traveled by the player in the game and then display it in our UI. Statistics and segmentation snap allows you to store unique metric values for each player. To add a statistics key, please follow the instructions below.
</Note>
1. Click on the **Statistics** widget to open the Statistics snaps configuration page.
1. Select the `Statistics` tool from the tool navigation and then click on the **+ Statistics** button. This will open up a form, where you can add the new statistics details. Add the following statistics and click save.
   1. `Key` - `distance_traveled`
1. Keep the default values for the rest of the fields.
    ![Statistics Config](/images/docs/tutorials/unity-sp-statistics.png)
1. Then click the back button to go back to the configuration home page.

### E. Storage Configuration
<Note>
    Storage snap allows you to store any non-structured or structured data for your game. In our case we want to store the color of the spaceship the user has selected. To add a storage key, please follow the instructions below.
</Note>
1. Click on the **Storage** widget to open the Storage snaps configuration page.
1. Select the `Blob Keys` tool from the tool navigation and then click on the **+ Blob Key** button. This will open up a form, where you can add the new blob key. Add the following details in the form and click save.
   1. `Blob Keys` - `color`
1. Keep the default values for the rest of the fields.
    ![Storage Config](/images/docs/tutorials/unity-sp-storage.png)

<Checkpoint step={3}>
  We have configured the Authentication, Leaderboard, Profiles, Statistics and Storage snaps. Our Snapend is now ready to integrate with our game.
</Checkpoint>

## Step 4: Download the Roblox SDK
1. On the Snapend home page scroll down to the SDK download widget called **Game Client SDKs**.
    - Select **Roblox - Lua** for the platform
    - Click Generate
![Roblox SDK](/images/docs/tutorials/roblox-sdk.png)
1. In a few minutes you will see a pop up of a Zip file. Download the zip file and extract it.
1. You will see a folder structure like this:
```bash
  ├── sdk-lua-roblox/
    │   ├── snapser/ (👈 This is the folder that you are going to need)
    │       └── api/
    │       └── model/
    │       └── wrapper/
```

<Note>
You will be copying the contents of `sdk-lua-roblox/snapser` folder into your Roblox projects `src/server/snapser`folder.
</Note>

## Step 6: Understand the Code
1. SnapserManager does all the heavy lifting of interfacing between the game code and the snapser SDK.
```lua
local authApi = require(game.ServerScriptService.Server.snapser.api.auth_service_api).new(nil, nil, {}) --dummy initialization
local profilesApi = require(game.ServerScriptService.Server.snapser.api.profiles_service_api).new(nil, nil, {}) --dummy initialization
local leaderboardsApi = require(game.ServerScriptService.Server.snapser.api.leaderboards_service_api).new(nil, nil, {}) --dummy initialization
local analyticsApi = require(game.ServerScriptService.Server.snapser.api.analytics_service_api).new(nil, nil, {}) --dummy initialization
local apiConstants = require(script.Parent.SnapserApiConstants)
local Utils = require(script.Parent.Utils)
local SnapserErrors = require(script.Parent.SnapserErrors)

local module = {}

module.PlayerLedger = {}

module.authCompleteEvent = Instance.new("BindableEvent", script)
module.authCompleteEvent.Name = "AutheticationComplete"

module.authRemovedEvent = Instance.new("BindableEvent", script)
module.authRemovedEvent.Name = "AutheticationRemoved"

module.refreshLeaderboardEvent = Instance.new("BindableEvent", script)
module.refreshLeaderboardEvent.Name = "RefreshLeaderboardEvent"

--#region Snapser Manager Functions

local function getPlayerLedgerEntryForUserId(userId)
    for index, value in pairs(module.PlayerLedger) do
        if (value.userId == userId) then
            return module[index]
        end
    end
end

function module:IsUserAuthenticated(userName)
    local ledgerEntry = module.PlayerLedger[userName]
    return ledgerEntry and ledgerEntry.userId and ledgerEntry.sessionToken
end

function module:IsUserProfileCreated(userName)
    local ledgerEntry = module.PlayerLedger[userName]
    return ledgerEntry and ledgerEntry.isProfileCreated
end

--#endregion

--#region Authentication

function module:loginUser(userName)
    local response = authApi:anon_login({ username = userName, create_user = true })
	if (response) then
		local currentUserId = response.user.id
		local currentSessionToken = response.user.session_token
        module.PlayerLedger[userName] = {
            userId = currentUserId,
            sessionToken = currentSessionToken
        }
		if (Utils:GetDictionaryCount(module.PlayerLedger) == 1) then
			module.authCompleteEvent:Fire(userName)
		end
		print(currentUserId .. " : " .. currentSessionToken .. " user created")
	end

    return response
end

function module:deleteUser(userName)
    local ledgerEntry = module.PlayerLedger[userName]
	if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
		local currentSessionToken = ledgerEntry.sessionToken
		local response = authApi:delete_user(currentUserId, currentSessionToken)
		if (response) then
			module.PlayerLedger[userName] = nil
			if (Utils:GetDictionaryCount(module.PlayerLedger) == 0) then
				module.authRemovedEvent:Fire()
			end
			print(currentUserId .. " deleted")
			return response
		end
	else
		print("No current user found. Try logging in before deleting the user.")
	end
end

--#endregion

--#region Profiles

function module:getProfile(userName, userId)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
		local currentSessionToken = ledgerEntry.sessionToken
        local response = profilesApi:get_profile(userId and userId or currentUserId, currentSessionToken)
        if (response) then
            print("Profile successfully fetched for userId " .. userId)
        end
        return response
    else
        print("Player not found for userId : " .. userId)
    end
end

function module:upsertProfile(userName, profileName)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
        local currentSessionToken = ledgerEntry.sessionToken
	    local response = profilesApi:upsert_profile(currentUserId, currentSessionToken, { profile = {name = profileName }})
	    if (response) then
		    module.PlayerLedger[userName].isProfileCreated = true
		    print("Profile created with the name " .. profileName .. " for userId " .. currentUserId)
	    end
	    return response
    else
        print( userName .. " : username not found.")
    end
end

function module:deleteProfile(userName)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
        local currentSessionToken = ledgerEntry.sessionToken
        local response = profilesApi:delete_profile(currentUserId, currentSessionToken)
        if (response) then
            module.PlayerLedger[userName].isProfileCreated = false
            print("Profile successfully deleted for userId " .. currentUserId)
        end
        return response
    else
        print( userName .. " : username not found.")
    end
end

--#endregion

--#region Leaderboard
function module:getLeaderboard(userName, getTopRange, count)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
        local currentSessionToken = ledgerEntry.sessionToken
        local range = getTopRange and apiConstants.leaderboardTopRange or apiConstants.leaderboardAroundRange
        local response = leaderboardsApi:get_scores(apiConstants.leaderboardName, range, count, currentSessionToken, currentUserId)
        if (response) then

        end
        return response
    else
        print( userName .. " : username not found.")
    end
end

function module:incrementLeaderboardScore(userName, value)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
        local currentSessionToken = ledgerEntry.sessionToken
        local response = leaderboardsApi:increment_score(apiConstants.leaderboardName, currentUserId, currentSessionToken, { delta = value } )
        if (response) then
            module.refreshLeaderboardEvent:Fire(userName)
        end
        return response
    else
        print( userName .. " : username not found.")
    end
end

function module:setLeaderboardScore(userName, value)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
        local currentSessionToken = ledgerEntry.sessionToken
        local response = leaderboardsApi:set_score(apiConstants.leaderboardName, currentUserId, currentSessionToken, { score = value } )
        if (response) then
            module.refreshLeaderboardEvent:Fire(userName)
        end
        return response
    else
        print( userName .. " : username not found.")
    end
end

--#endregion

--#region Profiles

function module:sendUserAnalyticsEvent(userName, analyticsEventData)
    local ledgerEntry = module.PlayerLedger[userName]
    if (ledgerEntry) then
        local currentUserId = ledgerEntry.userId
        local currentSessionToken = ledgerEntry.sessionToken
        local body = {user_id = currentUserId, properties = analyticsEventData.data}
        local response = analyticsApi:create_user_event(analyticsEventData.eventName, currentSessionToken, body)
        if (response) then
            print("Analytics event " .. analyticsEventData.eventName .. "/" .. analyticsEventData.data.action_type .. " sent for user " .. currentUserId)
        end
        return response
    else
        print( userName .. " : username not found.")
    end
end

--#endregion

return module
```
