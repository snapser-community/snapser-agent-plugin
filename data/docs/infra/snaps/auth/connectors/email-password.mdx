# Email Password Login

Click here to view all Auth Snap [connectors](/docs/infra/snaps/auth/connectors).

## Overview

This traditional email-password authentication method allows users to log in using their email and a user-defined password. Snapser sends a one-time password (OTP) to the user's email to validate ownership.

<Warning>
	All emails are lowercased before being stored in the database. This means that when a user signs up or logs in, their email will be converted to lowercase before being stored. This helps to prevent duplicate accounts with different email cases.
</Warning>

## Pre-requisite

Developers should reach out to their support team and nominate an email domain that will be used to send OTPs to users.

## How it works

To implement Email Password Login, developers must configure the connector via the Auth Configuration, Connector tool. Details on setting this up are available below in the "Configuration Tool" section.

### First time Login
1. The app client initiates an **EmailPasswordLogin** request using the user's email and password.
2. The Auth Snap checks if the user exists in the system.
3. If the user does not exist, the Auth Snap sends a response indicating that the user needs to verify their email viz. `email_verification_required: true`.
4. The Auth Snap sends an OTP to the user's email address.
5. The client then submits the OTP to the Auth Snap using the **VerifyEmail** API, which verifies its authenticity and issues a user ID and session token back to the app client.
6. The client can now use the user ID and session token to interact with other APIs on the Snapend.

### Subsequent Logins
For subsequent logins, the app client can directly use the **EmailPasswordLogin** request with the user's email and password. The Auth Snap will validate the credentials and return a user ID and session token if successful.

### Can I update a user's email?
Yes, there are two ways to update the email associated with a user's Email Password login:
1. <u>Game Client</u>: The app client can call the **ChangeEmail** API with the user's session token, the login type and the new email. See the "APIs" section below.
2. <u>Web Portal</u>: Developers can use the [User Manager](/docs/snapend/tools/user-manager) tool. In the user's Logins view, click the edit icon next to the login ID and enter the new email.

In both cases, the update will only succeed if the new email is not already attached to another account keychain.

<Warning>
	Once the email has been updated, the user will no longer be able to log in with their previous email.
</Warning>

<Note>
  You can use the Custom Email Template tool to customize the email that goes out to your users.
</Note>

## Usage

Developers have the option to start user sessions with an Anonymous login and later upgrade to a secure Email password login, or they can begin directly with an Email password login. If opting for the latter, simply store and utilize the user ID and session token returned by the Auth Snap to interact with other APIs on your Snapend.
For upgrading from an Anonymous to an Email Password login, follow the example below.

### Example

1. A app client initiates an AnonLogin request using the device's unique identifier as the username.
1. The Auth Snap generates a new user with `user_id=395d9b91-72fd-40f2-a3cd-cf5a1e7a604f` and `session_token=9a052312-48f6-4710-a072-230ddd046a2d`.
1. The client displays a prompt for the user to secure their account by entering an email and a password.
1. The client makes a request to the **EmailPasswordLogin** API and gets a response `email_verification_required: true`.
1. The Authentication snap in parallel, sends an OTP to the user's email address.
1. The client then submits this OTP using the **VerifyUser** endpoint.
6. A new **user_id** and **session_token** are generated for the email password account and sent back to the caller.
7. To merge these accounts, the client uses the **AssociateLogins** API, specifying which credentials to retain or discard.
8. The Auth Snap then consolidates the accounts based on these preferences.

## Configuration Tool

To enable Email Password authentication, select **Email Password** from the connector menu, which will show you a dialog with a form. Snapser needs the following details to activate your connector.

### Basic Password Settings
1. <u>Regex Pattern</u>: The pattern that the password should match. This is a regex pattern that will be used to validate the password. For example, if you want to enforce a minimum length of 8 characters, you can use the regex pattern `^(?=.{8,})`. You can also use other regex patterns to enforce other rules like special characters, numbers, etc.
2. <u>Allow Update with old password</u>: If this is toggled, the user can set a new password based on an old password. Without this, the user has to initiate a password reset using a OTP sent to their email.

### Email Verification and Account Recovery Settings
1. <u>OTP Length</u>: The length of the OTP that will be sent to the user's email. This is a number that will be used to generate the OTP. For example, if you want to generate a 6 digit OTP, you can set this to 6. This setting must be between 4 and 10 inclusive.
1. <u>OTP Validity</u>: The time in minutes for which the OTP is valid. After this time, the OTP will expire and the user will have to request a new one. You can set a value between 5 and 60 minutes.
