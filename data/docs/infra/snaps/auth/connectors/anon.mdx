# Anonymous Login

Click here to view all Auth Snap [connectors](/docs/infra/snaps/auth/connectors).

## Overview

Anonymous Login allows users to access your app without providing personal details. This feature is particularly useful for apps and games that aim to provide a frictionless initial user experience for those hesitant to commit their personal information immediately.

## How it works

The **Anonymous Login** API requires a **username**, which can be any string, though it is common to use a unique device identifier or a random string to minimize collision risks. The request should include **create_user=true** to create a new user if one does not already exist.

Upon anonymous login, users are assigned a unique user ID and session token, which should be stored securely, such as in local storage or a keychain.

<Note>
  Anonymous Login accounts are inherently insecure. If the username (e.g., a device's unique identifier) is compromised, it could lead to user impersonation. It is advisable to prompt users to enhance their account security by linking additional authentication methods such as email or third-party auth.
</Note>

## Usage

Developers are encouraged to guide users from Anonymous Login to a more secure method post-initial experience. This is typically done by prompting users to add an email address or third-party authentication method.

## Securing the Account

To secure an account, utilize the [AssociateLogins](#associatelogins-api) API to link the Anonymous Login with an email or third-party auth account. This retains the user’s data and progress while allowing for secure logins with the new methods.

### Example

1. A game client initiates an AnonLogin request using the device's unique identifier as the username.
2. The Auth Snap generates a new user with `user_id=395d9b91-72fd-40f2-a3cd-cf5a1e7a604f` and `session_token=9a052312-48f6-4710-a072-230ddd046a2d`.
3. The client displays a prompt for the user to secure their account by entering an email.
4. The client requests an OTP from the **OTP** API, which the Auth Snap sends to the provided email.
5. The client submits an **EmailLogin** request with the email and OTP.
6. A new **user_id** and **session_token** are generated for the email account.
7. To merge these accounts, the client uses the **AssociateLogins** API, specifying which credentials to retain or discard.
8. The Auth Snap then consolidates the accounts based on these preferences.

This process ensures that even if the anonymous username is compromised, unauthorized access through the AnonLogin API is prevented.

<Note>
  Similarly, you can encourage users to link additional third-party accounts, continuously enhancing their account security.
</Note>
