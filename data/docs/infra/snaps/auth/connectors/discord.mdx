# Discord Login

Click here to view all Auth Snap [connectors](/docs/infra/snaps/auth/connectors).

## Overview

Discord is a popular communication platform for gamers, and integrating Discord login into your game can enhance user experience by allowing players to log in using their existing Discord accounts. This guide will help you set up Discord login for your game using the Snapser platform.

## Setup Requirements
You need to have a Discord app in the Discord Developer Portal

### 1. Create a Discord App
- Go to Discord Developer Websites [applications page](https://discord.com/developers/applications).
- Click on the "New Application" button.
- Enter a name for your application and click "Create".
- Navigate to the "OAuth2" tab on the left sidebar.
- Here you will see your **Client ID** and **Client Secret**. You will need these for the configuration.
- Note, if you are creating this app for the first time, you may have to click on the **Reset Secret** button to generate your secret key.

![DiscordAppCreate](/images/docs/tutorials/discord-app-id-secret.png)

## How it works

To implement Discord Login, game studios must configure the connector via the Auth Configuration, Connector tool. Details on setting this up are available below in the "Configuration Tool" section.

After configuration, the studio should integrate the [Discord SDK](https://discord.com/developers/docs/discord-social-sdk/getting-started) for the relevant platform into the game client. Discord has plugins for both Unity and Unreal. The Discord SDK, upon successful authentication, returns an access_token which should then be sent to the Auth snap. The Auth Snap receives this access_token, verifies its authenticity with Discords's servers, and if valid, issues a user ID and session token back to the game client. This enables user authentication within the game.

Let's dive into both these steps in detail below.

## Configuration Tool
The Discord Connector configuration tool needs the following details:

### Credentials
These credentials can be found in your Discord Apps - OAuth2 section.
1. <u>Client Id</u> - The **client_id** of your application. This is a unique identifier for your app.
2. <u>Client Secret</u> - A secret that Discord generates for your app. Please do not share this secret with anyone. This is used to authenticate your app with Discord.

#### Setting up SDK Event Handling
Let's add some event handlers to monitor what's happening with our Discord connection. We'll set up two important callbacks:
- A logging callback to see what the SDK is doing
- A status callback to know when we can start using Discord features

Lets now add the following code to the `DiscordManager.cs` script:
```csharp
void Start()

    {
        // loginButton.onClick.AddListener(StartOAuthFlow);

    // Set initial status text

        statusText.text = "Ready to login";

}

    Debug.Log($"Status changed: {status}");
    statusText.text = status.ToString();
    if (error != Client.Error.None)
    {
        Debug.LogError($"Error: {error}, code: {errorCode}");
    }
```

#### Account Linking with Discord
This is the part that does the OAuth2 authentication. As part of this we will:
1. Open the Discord app or a browser window for Discord login
1. Get an authorization code
1. Exchange it for an access token
1. Connect to Discord

Lets add the following code to the `DiscordManager.cs` script:
```csharp
private void StartOAuthFlow()
{
    var authorizationVerifier = client.CreateAuthorizationCodeVerifier();
    codeVerifier = authorizationVerifier.Verifier();

    var args = new AuthorizationArgs();
    args.SetClientId(clientId);
    args.SetScopes(Client.GetDefaultPresenceScopes());
    args.SetCodeChallenge(authorizationVerifier.Challenge());
    client.Authorize(args, OnAuthorizeResult);
}

private void OnAuthorizeResult(ClientResult result, string code, string redirectUri)
{
    Debug.Log($"Authorization result: [{result.Error()}] [{code}] [{redirectUri}]");
    if (!result.Successful())
    {
        return;
    }
    GetTokenFromCode(code, redirectUri);
}

private void GetTokenFromCode(string code, string redirectUri)
{
    client.GetToken(clientId,
                    code,
                    codeVerifier,
                    redirectUri,
                    (result, token, refreshToken, tokenType, expiresIn, scope) =>
                    {});
}
```

#### Initialize the SDK

- Now let's add the implementation of these functions to the `DiscordSocialUnrealCharacter.cpp` file.
- In the `DiscordSocialUnrealCharacter.cpp` file, add the following code:
```cpp
#define APPLICATION_ID 1111111111111111111

void ADiscordSocialUnrealCharacter::BeginPlay()
{
    auto PlayerController = Cast<APlayerController>(GetController());
    auto LocalPlayer = PlayerController->GetLocalPlayer();
    Discord = ULocalPlayer::GetSubsystem<UDiscordLocalPlayerSubsystem>(LocalPlayer);
    auto LogCallback = FDiscordClientLogCallback::CreateUObject(this, &ADiscordSocialUnrealCharacter::OnLogMessage);
    FScriptDelegate StatusChanged;
    StatusChanged.BindUFunction(this, "OnStatusChanged");
    Discord->Client->AddLogCallback(LogCallback, EDiscordLoggingSeverity::Info);
    Discord->OnStatusChanged.Add(StatusChanged);
}

void ADiscordSocialUnrealCharacter::DiscordConnect()
{
    CodeVerifier = Discord->Client->CreateAuthorizationCodeVerifier();
    auto AuthArgs = NewObject<UDiscordAuthorizationArgs>();
    AuthArgs->Init();
    AuthArgs->SetClientId(APPLICATION_ID);
    AuthArgs->SetScopes(UDiscordClient::GetDefaultPresenceScopes());
    AuthArgs->SetCodeChallenge(CodeVerifier->Challenge());
    Discord->Client->Authorize(AuthArgs, FDiscordClientAuthorizationCallback::CreateUObject(this, &ADiscordSocialUnrealCharacter::OnAuthorizeCompleted));
}

void ADiscordSocialUnrealCharacter::OnLogMessage(FString Message, EDiscordLoggingSeverity Severity)
{
    UE_LOG(LogTemplateCharacter, Log, TEXT("[%s] %s"), *UEnum::GetValueAsString(Severity), *Message);
}

void ADiscordSocialUnrealCharacter::OnStatusChanged(EDiscordClientStatus Status, EDiscordClientError Error, int32 ErrorDetail)
{
    UE_LOG(LogTemplateCharacter, Log, TEXT("Connection status: %s"), *UEnum::GetValueAsString(Status));
    if (Status == EDiscordClientStatus::Ready)
    {
        UE_LOG(LogTemplateCharacter, Log, TEXT("Connected to Discord! Ready to go! You can now start using Discord features."));
    }
    else if (Error != EDiscordClientError::None)
    {
        UE_LOG(LogTemplateCharacter, Log, TEXT("Connection error: %s (Detail: %d)"), *UEnum::GetValueAsString(Error), ErrorDetail);
    }
}

void ADiscordSocialUnrealCharacter::OnAuthorizeCompleted(UDiscordClientResult* Result, FString Code, FString RedirectUri)
{
    if (!Result->Successful())
    {
        UE_LOG(LogTemplateCharacter, Error, TEXT("Discord authorization failed: %s"), *Result->Error());
        return;
    }

    UE_LOG(LogTemplateCharacter, Log, TEXT("Authorization successful! Getting access token..."));
    Discord->Client->GetToken(APPLICATION_ID, Code, CodeVerifier->Verifier(), RedirectUri, FDiscordClientTokenExchangeCallback::CreateUObject(this, &ADiscordSocialUnrealCharacter::OnTokenExchange));
}

void ADiscordSocialUnrealCharacter::OnTokenExchange(UDiscordClientResult* Result, FString AccessToken, FString RefreshToken, EDiscordAuthorizationTokenType TokenType, int32 ExpiresIn, FString Scope)
{
    if (!Result->Successful())
    {
        UE_LOG(LogTemplateCharacter, Error, TEXT("Discord token exchange failed: %s"), *Result->Error());
    }

    Discord->Client->UpdateToken(TokenType, AccessToken, FDiscordClientUpdateTokenCallback::CreateUObject(this, &ADiscordSocialUnrealCharacter::OnTokenUpdated));
}

void ADiscordSocialUnrealCharacter::OnTokenUpdated(UDiscordClientResult* Result)
{
    Discord->Client->Connect();
}
```

#### What's Happening Here?
1. We create a code verifier for OAuth2 PKCE security
1. Set up authorization arguments with your app ID and required scopes
1. Start the auth flow with `Client::Authorize`, which opens a browser
1. When authorized, we exchange the code for an access token
1. `Client::UpdateToken` tells the SDK to use our access token for Discord API calls
1. Once the token is updated, we call `Client::Connect`, and the SDK will begin connecting asynchronously

### C. Discord Activities
Discord activities are SPAs that run inside the Discord client in an iframe. The Discord Social Unity and Unreal SDKs do not work in WebGl builds. To run a Discord activity while having access to Discord features, you need to use the [Embedded App SDK](https://discord.com/developers/docs/developer-tools/embedded-app-sdk). If you are making a web game using HTML/JS/CSS this is straightforward. However, if you want to use your game written in Unity C# and make a WebGl build, we recommend that you use Dissonity. Snapser has forked this project and is available in a [repo](https://github.com/snapser-community/Dissonity) under the snapser-community organization. Following the installation instructions, you will get the **access_token** bubbled up to your Unity C# code. You can then use the DiscordLogin API to authenticate the user.

We have added a sample guide that shows you how to get a Unity game working in a Discord activity. You can follow the [guide](/docs/guides/samples/unity-discord) to know more.


## Usage

Game studios have the option to start user sessions with an Anonymous login and later upgrade to a secure Discord login, or they can begin directly with an Discord login. If opting for the latter, simply store and utilize the user ID and session token returned by the Auth Snap to interact with other APIs on your Snapend. For upgrading from an Anonymous to an Discord login, follow the example below.

### Example

1. Assume a game client initiates an AnonLogin request using the device's unique identifier as the username.
2. The Auth Snap generates a new user profile with `user_id=395d9b91-72fd-40f2-a3cd-cf5a1e7a604f` and `session_token=9a052312-48f6-4710-a072-230ddd046a2d`.
3. The game client prompts the user to secure their account via Discord Login, initiating the OAuth2 flow described above.
4. As part of the flow, the client receives an **access_token**.
5. Next, the client submits an **DiscordLogin** request with the **access_token** and sets **create_user=true**.
6. The client receives a new **user_id** and **session_token** linked to the Discord account.
7. To merge these accounts, the client utilizes the **AssociateLogins** API, specifying which account to retain and which to discard.
8. The Auth Snap finalizes the association, discarding the unwanted user ID and token, preserving the necessary ones.

This procedure ensures the account remains secure, as access cannot be gained merely through knowing the username used in the AnonLogin API.
