# Email Login

Click here to view all Auth Snap [connectors](/docs/infra/snaps/auth/connectors).

## Overview

Email Login is a secure method of authenticating users by sending a one-time password (OTP) to their email address. This method is more secure than traditional password-based authentication, as it does not require storing or transmitting passwords.

<Warning>
	All emails are lowercased before being stored in the database. This means that when a user signs up or logs in, their email will be converted to lowercase before being stored. This helps to prevent duplicate accounts with different email cases.
</Warning>

## Pre-requisite

Developers should reach out to the Snapser Support team and nominate an email domain that will be used to send OTPs to users.

## How it works

To implement Email Login, developers must configure the connector via the Auth Configuration, Connector tool.
Details on setting this up are available below in the "Configuration Tool" section.

After configuration, the studio can initiate an Email Login request from the app client. The Auth Snap sends an OTP to the user's email address. The client then submits the OTP to the Auth Snap, which verifies its authenticity and issues a user ID and session token back to the app client. This enables user authentication within the app.

<Note>
  You can use the Custom Email Template tool to customize the email that goes out to your users.
</Note>

### Is there support for passwords?
Yes, if you want a more traditional email password authentication method, you can use the Email Password connector. This connector allows you to authenticate users using a valid email and password.

### Can I update a user's email?
Yes, there are two ways to update the email associated with a user's Email login:
1. <u>Game Client</u>: The app client can call the **ChangeEmail** API with the user's session token, the login type and the new email. See the "APIs" section below.
2. <u>Web Portal</u>: Developers can use the [User Manager](/docs/snapend/tools/user-manager) tool. In the user's Logins view, click the edit icon next to the login ID and enter the new email.

In both cases, the update will only succeed if the new email is not already attached to another account keychain.

<Warning>
	Once the email has been updated, the user will no longer be able to log in with their previous email.
</Warning>

## Usage

Developers have the option to start user sessions with an Anonymous login and later upgrade to a secure Email login, or they can begin directly with an Email login. If opting for the latter, simply store and utilize the user ID and session token returned by the Auth Snap to interact with other APIs on your Snapend. For upgrading from an Anonymous to an Email login, follow the example below.

### Example

1. A app client initiates an AnonLogin request using the device's unique identifier as the username.
2. The Auth Snap generates a new user with `user_id=395d9b91-72fd-40f2-a3cd-cf5a1e7a604f` and `session_token=9a052312-48f6-4710-a072-230ddd046a2d`.
3. The client displays a prompt for the user to secure their account by entering an email.
4. The client requests an OTP from the **OTP** API, which the Auth Snap sends to the provided email.
5. The client submits an **EmailLogin** request with the email and OTP.
6. A new **user_id** and **session_token** are generated for the email account.
7. To merge these accounts, the client uses the **AssociateLogins** API, specifying which credentials to retain or discard.
8. The Auth Snap then consolidates the accounts based on these preferences.

## Configuration Tool

To enable Email authentication, select **Email** from the connector menu, which will show you a dialog
with a form. Snapser needs the following details to activate your connector.

### One-time-password settings
1. <u>Length</u>: The length of the one-time-password. For example: entering 5 will mean the Snapser
   generated one-time-password will be something like 53982. Typically people chose a number
   between 5-8.
2. <u>Validity</u>: This should be the number of minutes the one-time-password should remain valid for.
   If a user enters a correct one-time-password after this expiry, the auth snap will not accept it.
   The user then will be forced to initiate a new one-time-password generation. Typically
   you want to keep your expiry between 5 to 15 minutes.

## Custom Email Template Tool
Snapser allows you to fully modify the email that goes out to your users. You can customize the
email subject, and body. The only requirement is that your template should have the following variables
in the body of the email:
1. **.OTP**: This will be replaced by the one-time-password generated by Snapser.
2. **.TTL**: This will be replaced by the validity of the one-time-password in minutes.

<Note>
  Snapser uses the dot notation to replace the variables in your email template. For example,
  You need to use `{{.OTP}}` and `{{.TTL}}` in your email template.
</Note>
