# X Login

Click here to view all Auth Snap [connectors](/docs/infra/snaps/auth/connectors).

## Overview

X (formerly Twitter) Login is a connector that allows users to log into your application using their X credentials.
This connector leverages the [X OAuth 2.0 API](https://developer.x.com/en/docs/authentication/using-oauth-2.0) to ensure a smooth and secure login experience.

## Setup Requirements

### Step 1: Create an X Developer Account

* Visit the [X Developer Portal](https://developer.x.com/) and sign up or log in.
* Create a new Project and App.
* Under the App settings, generate the `Client ID` and `Client Secret`.
* Set a valid Callback URL for your game or app that the X auth flow will redirect to after authentication.

## How it works

To implement X Login, developers must configure the connector via the Auth Configuration, Connector tool. X uses OAuth 2.0 PKCE flow for user authentication. Once setup is complete:

1. Integrate X's OAuth 2.0 login flow in your app client.
1. The player authenticates via X's UI and grants permission to your app.
1. X returns a `code` to your client.
1. At this point, you can either:

   * Exchange the `code` for an `access_token` yourself, and then use the `access_token` to call the Snapser Auth Snap.
   * Or pass the `code`, `code_verifier`, and `redirect_uri` directly in the Snapser Auth Snap to handle the token exchange for you.

If you choose to exchange the `code` for an `access_token` yourself, your `XLogin` API call will look like this:

```json
{
  "access_token": "string",
  "create_user": true
}
```

If you prefer Snapser to handle the token exchange, you can send the appropriate `code`, `code_verifier`, and `redirect_uri` to the Snapser Auth Snap:

```json
{
  "code": "string",
  "code_verifier": "string",
  "redirect_uri": "string",
  "create_user": true
}
```

Finally, the Auth Snap verifies the details with X and issues a user ID and session token.

You can either:

* Start users as anonymous and upgrade to X login later.
* Or directly begin the session with X login.

Details below.

## Integration with X Authentication APIs

Unlike Facebook or Google, X does not offer official SDKs for Unity or Unreal. You must implement OAuth manually or use community SDKs.

### Unity Integration

To integrate X login in Unity:

1. Launch an in-app web view that opens the X OAuth 2.0 authorization URL.
2. Let the user authorize your app and be redirected back with a `code`.
3. Exchange the code for an `access_token` using your backend or client (not recommended from client).
4. Submit the `access_token` to Snapser's Auth Snap via the `XLogin` API.

You can also use third-party Unity plugins for OAuth2 that support webview authentication.

### Unreal Engine Integration

Similar to Unity, you’ll use an in-app browser:

1. Open the X OAuth 2.0 URL.
2. Handle the redirect URI to capture the `code`.
3. Exchange it for the token via backend.
4. Send token to Snapser Auth Snap.

Manual implementations or community plugins (e.g., VaRest + WebBrowser) can be used.

## Usage

Developers can begin with Anonymous login and later upgrade to X login, or begin directly with X login. Store the `user_id` and `session_token` returned from the Auth Snap to continue session-based gameplay or app experience.

### Example

1. App client calls `AnonLogin` with a unique device ID.
2. Auth Snap returns:

   * `user_id=abc123`
   * `session_token=xyz789`
3. User decides to link their account to X.
4. Client launches OAuth 2.0 login, retrieves `access_token` from X.
5. Client calls `XLogin` with `create_user=true`.
6. Auth Snap returns a new `user_id` + `session_token` tied to the X account.
7. Use `AssociateLogins` to merge the two accounts.

This ensures secure upgrades without exposing internal identifiers.
