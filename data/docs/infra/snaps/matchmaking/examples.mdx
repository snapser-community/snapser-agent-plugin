# Matchmaking Profile Examples

This page provides a collection of ready-to-use Match Profile examples covering common game matchmaking scenarios. Each example includes a full JSON configuration along with an explanation of why each setting is configured the way it is.

You can use these as starting templates and adapt them to your game's needs. For detailed documentation on each field, see the [Matchmaking Snap](/docs/infra/snaps/matchmaking) reference.

## Simple 1v1 Duel

A minimal matchmaking profile for a 1v1 game mode where two players are matched based on their Elo rating. The Elo filter uses auto expansion to gradually widen the search range, ensuring players find a match even during low-population periods.

```json
{
  "name": "duel-1v1",
  "description": "Simple 1v1 duel with Elo-based matching",
  "is_active": true,
  "min_players": 2,
  "max_players": 2,
  "match_acceptance_settings": {
    "enabled": false,
    "timeout_seconds": "0"
  },
  "backfill_settings": null,
  "delay_partial_match_seconds": 0,
  "assignment_settings": null,
  "host_selection_settings": {
    "enabled": false,
    "key": "",
    "operator": "min"
  },
  "queue_settings": {
    "enabled": false,
    "max_party_size": 0,
    "min_party_size": 0
  },
  "team_formation_settings": {
    "enabled": true,
    "num_teams": 2,
    "min_players_per_team": 1,
    "allow_party_separation": false,
    "strategy": "TEAM_FORMATION_ALTERNATE",
    "strategy_arg": "elo"
  },
  "pools": [
    {
      "name": "elo-pool",
      "applies_after_seconds": "0",
      "applies_for_seconds": "99999999",
      "double_range_filters": [
        {
          "double_arg": "elo",
          "start": 0,
          "end": 0,
          "is_absolute": false,
          "auto_expansion": {
            "initial_start": 0,
            "initial_end": 0,
            "interval_seconds": 5,
            "spread_amount": 100,
            "max_spread": 99999999,
            "spread_strategy": "AUTO_EXPANSION_BALANCED"
          },
          "expansion_steps": [],
          "expansion_formation_strategy": "UNSPECIFIED"
        }
      ],
      "string_equals_filters": [],
      "tag_present_filters": [],
      "statistics_filters": [],
      "leaderboard_filters": [],
      "latency_filter": null,
      "bot_filter": null
    }
  ],
  "metadata": {}
}
```

**Key points:**

- **Team formation** uses `TEAM_FORMATION_ALTERNATE` with `elo` as the strategy argument. This means the two players are placed on opposing teams sorted by Elo so that matches are competitively balanced.
- **Auto expansion** starts with a tight range (0 spread) and expands by 100 Elo every 5 seconds. This ensures players are matched closely at first, but the range widens quickly so no one waits forever.
- **No allocation** is set (`assignment_settings: null`). Add a fleet or lobby allocation if your game needs a dedicated server.

## Casual 5v5 Team Match

A casual team game mode where 10 players are split into 2 teams of 5. Players select a game mode via a custom string argument (e.g., `"casual"`), and there are no strict skill-based filters. The `delay_partial_match_seconds` setting gives the matchmaker extra time to fill the lobby before starting with fewer players.

```json
{
  "name": "casual-5v5",
  "description": "Casual 5v5 team match with flexible player count",
  "is_active": true,
  "min_players": 8,
  "max_players": 10,
  "match_acceptance_settings": {
    "enabled": false,
    "timeout_seconds": "0"
  },
  "backfill_settings": {
    "enabled": true,
    "timeout_seconds": "60"
  },
  "delay_partial_match_seconds": 30,
  "assignment_settings": null,
  "host_selection_settings": {
    "enabled": false,
    "key": "",
    "operator": "min"
  },
  "queue_settings": {
    "enabled": false,
    "max_party_size": 0,
    "min_party_size": 0
  },
  "team_formation_settings": {
    "enabled": true,
    "num_teams": 2,
    "min_players_per_team": 4,
    "allow_party_separation": false,
    "strategy": "TEAM_FORMATION_UNSPECIFIED",
    "strategy_arg": ""
  },
  "pools": [
    {
      "name": "casual",
      "applies_after_seconds": "0",
      "applies_for_seconds": "600",
      "double_range_filters": [],
      "string_equals_filters": [
        {
          "string_arg": "game_mode",
          "value": "casual"
        }
      ],
      "tag_present_filters": [],
      "statistics_filters": [],
      "leaderboard_filters": [],
      "latency_filter": null,
      "bot_filter": null
    }
  ],
  "metadata": {}
}
```

**Key points:**

- **Flexible player count**: `min_players: 8` and `max_players: 10` means the match can start with as few as 8 players (4 per team) but ideally fills to 10.
- **Delay partial match**: Set to 30 seconds. If only 8-9 players are found, the matchmaker waits 30 seconds before forming the match, giving time for a 10th player to join.
- **Backfilling**: Enabled with a 60-second window. After the match starts, additional players can join to fill empty slots within a minute.
- **String equals filter**: Only tickets with `game_mode = "casual"` in their `string_args` will be matched together. The game client passes this when creating a ticket.
- **Team formation**: Uses the default strategy (least populated), which randomly assigns players to teams while keeping party members together.

- **Statistics filter (MMR)**: Uses `ranked_mmr` as a relative counter-type stat with auto expansion. Starts tight (0 spread), expands by 100 MMR every 30 seconds, capped at 500 total spread. The matchmaker automatically fetches each player's `ranked_mmr` from the Statistics snap.
- **Latency filter**: Uses manual expansion steps. For the first 60 seconds, only matches players with sub-80ms latency. Then widens to 150ms, and finally 250ms after 2 minutes. This ensures low-latency matches when possible but doesn't leave players stranded.
- **Team formation**: `TEAM_FORMATION_ALTERNATE` with `ranked_mmr` ensures teams are balanced by distributing high and low MMR players across both teams.

## Skill-Tiered Matchmaking with Multiple Pools

A profile that uses multiple pools with tag filters to separate players into skill tiers. Lower-skilled players are matched together in one pool, while higher-skilled players are matched in another. Each pool can have its own expansion rules. This pattern is useful for games that want to protect new or lower-skilled players from being matched against veterans.

```json
{
  "name": "tiered-matchmaking",
  "description": "Skill-tiered 1v1 with separate pools for beginners and experienced players",
  "is_active": true,
  "min_players": 2,
  "max_players": 2,
  "match_acceptance_settings": {
    "enabled": false,
    "timeout_seconds": "0"
  },
  "backfill_settings": null,
  "delay_partial_match_seconds": 0,
  "assignment_settings": null,
  "host_selection_settings": {
    "enabled": false,
    "key": "",
    "operator": "min"
  },
  "queue_settings": {
    "enabled": false,
    "max_party_size": 0,
    "min_party_size": 0
  },
  "team_formation_settings": {
    "enabled": true,
    "num_teams": 2,
    "min_players_per_team": 1,
    "allow_party_separation": false,
    "strategy": "TEAM_FORMATION_UNSPECIFIED",
    "strategy_arg": ""
  },
  "pools": [
    {
      "name": "beginners",
      "applies_after_seconds": "0",
      "applies_for_seconds": "1800",
      "double_range_filters": [
        {
          "double_arg": "skill_rating",
          "start": 0,
          "end": 0,
          "is_absolute": false,
          "auto_expansion": null,
          "expansion_steps": [
            {
              "applies_after_seconds": 0,
              "applies_for_seconds": 1800,
              "start": 0,
              "end": 0
            }
          ],
          "expansion_formation_strategy": "UNSPECIFIED"
        }
      ],
      "string_equals_filters": [
        {
          "string_arg": "queue_mode",
          "value": "ranked"
        }
      ],
      "tag_present_filters": [
        {
          "tag": "beginner"
        }
      ],
      "statistics_filters": [],
      "leaderboard_filters": [],
      "latency_filter": null,
      "bot_filter": null
    },
    {
      "name": "experienced",
      "applies_after_seconds": "0",

        {
          "double_arg": "skill_rating",
          "start": 0,
          "end": 0,

            {
              "applies_after_seconds": 0,
              "applies_for_seconds": 30,

              "applies_after_seconds": 30,

        }
      ],
      "string_equals_filters": [
        {
          "string_arg": "queue_mode",
          "value": "ranked"
        }
      ],
      "tag_present_filters": [
        {
          "tag": "experienced"
        }
      ],
      "statistics_filters": [],
      "leaderboard_filters": [],
      "latency_filter": null,
      "bot_filter": null
    }
  ],
  "metadata": {}
}
```

**Key points:**

- **Two pools**: The `beginners` pool matches players tagged with `beginner`, while the `experienced` pool matches players tagged with `experienced`. The game client sets the appropriate tag when creating a ticket based on the player's account level, games played, or other criteria.
- **Different expansion behavior**: The beginner pool keeps a tight range throughout (protecting new players from large skill gaps). The experienced pool uses manual expansion steps that progressively widen every 30 seconds, since experienced players are generally more tolerant of skill differences and faster queue times matter more.
- **String equals filter**: Both pools also require `queue_mode = "ranked"`, ensuring only ranked-queue tickets are evaluated.
- **Tags are set by the client**: When creating a ticket, the game client includes the tag (e.g., `"tags": ["beginner"]`) in the `search_fields`. The matchmaker uses this to route the ticket to the appropriate pool.

## Lobby-Based Match with Countdown

A profile that allocates matches to Snapser lobbies instead of directly to a fleet. After the match is formed, a lobby is created with a configurable delay before it starts, giving players time to select loadouts, view the match roster, or ready up. This is common for games with a pre-match lobby phase.

```json
{
  "name": "lobby-match",
  "description": "Standard match with lobby allocation and pre-match countdown",
  "is_active": true,
  "min_players": 8,
  "max_players": 10,
  "match_acceptance_settings": {
    "enabled": true,
    "timeout_seconds": "12"
  },
  "backfill_settings": null,
  "delay_partial_match_seconds": 15,
  "assignment_settings": {
    "fleet_name": "lobby-fleet",
    "geo": [
      "oregon",
      "singapore"
    ],
    "id": "",
    "lobby_start_after_seconds": 30,
    "metadata": {
      "map": "arena_01",
      "match_type": "standard"
    },
    "type": "lobby"
  },
  "host_selection_settings": {
    "enabled": false,
    "key": "",
    "operator": "min"
  },
  "queue_settings": {
    "enabled": false,
    "max_party_size": 0,
    "min_party_size": 0
  },
  "team_formation_settings": {
    "enabled": true,
    "num_teams": 2,
    "min_players_per_team": 4,
    "allow_party_separation": false,
    "strategy": "TEAM_FORMATION_UNSPECIFIED",
    "strategy_arg": ""
  },
  "pools": [
    {
      "name": "standard",
      "applies_after_seconds": "0",
      "applies_for_seconds": "600",
      "double_range_filters": [],
      "string_equals_filters": [
        {
          "string_arg": "queue",
          "value": "standard"
        }
      ],
      "tag_present_filters": [],
      "statistics_filters": [],
      "leaderboard_filters": [],
      "latency_filter": null,
      "bot_filter": null
    }
  ],
  "metadata": {}
}
```

**Key points:**

- **Lobby allocation**: `type: "lobby"` creates a Snapser lobby instead of directly allocating a fleet server. The `fleet_name` and `geo` tell the lobby which fleet and regions to use when it eventually starts.
- **Lobby start delay**: `lobby_start_after_seconds: 30` gives players 30 seconds in the lobby before the game server is allocated and the match begins. This is passed as `start_after_seconds` in the match data.
- **Allocation metadata**: `map` and `match_type` are passed into the lobby's `allocation_metadata`, which the game server can read to configure the match.
- **Match acceptance + delay**: Match acceptance (12s timeout) ensures all players are present, and `delay_partial_match_seconds: 15` gives extra time to find a full 10-player lobby before settling for 8.

## Free-For-All with Bot Backfill

A free-for-all mode where up to 8 players compete individually (no teams). If the matchmaker cannot find enough real players, bots are used to fill the remaining slots. This keeps queue times short in low-population scenarios.

```json
{
  "name": "ffa-with-bots",
  "description": "Free-for-all with bot backfill for low population",
  "is_active": true,
  "min_players": 8,
  "max_players": 8,
  "match_acceptance_settings": {
    "enabled": false,
    "timeout_seconds": "0"
  },
  "backfill_settings": null,
  "delay_partial_match_seconds": 0,
  "assignment_settings": null,
  "host_selection_settings": {
    "enabled": false,
    "key": "",
    "operator": "min"
  },
  "queue_settings": {
    "enabled": false,
    "max_party_size": 0,
    "min_party_size": 0
  },
  "team_formation_settings": {
    "enabled": false,
    "num_teams": 0,
    "min_players_per_team": 0,
    "allow_party_separation": false,
    "strategy": "TEAM_FORMATION_UNSPECIFIED",
    "strategy_arg": ""
  },
  "pools": [
    {
      "name": "ffa",
      "applies_after_seconds": "0",
      "applies_for_seconds": "300",
      "double_range_filters": [],
      "string_equals_filters": [
        {
          "string_arg": "game_mode",
          "value": "ffa"
        }
      ],
      "tag_present_filters": [],
      "statistics_filters": [],
      "leaderboard_filters": [],
      "latency_filter": null,
      "bot_filter": {
        "chance": 100
      }
    }
  ],
  "metadata": {}
}
```

**Key points:**

- **No team formation**: `enabled: false` with `num_teams: 0` means players are not split into teams. This is a true free-for-all.
- **Bot filter**: `chance: 100` means if there aren't enough real players, the matchmaker will always fill remaining slots with bot tickets (tagged with `bot`). Your game server can check for this tag to spawn AI-controlled players. Set `chance` to a lower value (e.g., 50) to only sometimes fill with bots.
- **String filter**: Only tickets with `game_mode = "ffa"` are considered, separating this queue from other game modes.
