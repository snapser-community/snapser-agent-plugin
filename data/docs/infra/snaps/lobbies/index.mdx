# Lobbies

The Lobbies snap provides games with the ability to create ephemeral pre-game lobbies. These groups can be used to handle game mode selection, player readiness checks, and other pre-game activities.

## Lobby Categories

The Lobbies snap supports the following categories:

1. **Public**: As the name suggests, any user can choose to join these type of lobbies at any time, as long as the lobby has not reached its `max_members` limit.
2. **Private**: Users cannot join private lobbies directly and private lobbies will not show up in a `ListLobbies` search request. Only the lobby owner can add users to a private lobby.

## Lobby Ownership
Users can belong to one of the two categories:
1. **Owners**: Every private lobby has an owner.
2. **Non-Owners**: They can be a part of public or private lobbies.

### Owners
By default, Lobby owners are the users who created the party. They have the ability to update the party, add or remove members, and delete the party.

If a lobby owner leaves the lobby, lobby ownership is transferred to another party member. Lobby owners can also transfer ownership to another member explicitly via the `TransferOwner` API.

### Non-owners
Non-owners can join public lobbies and private lobbies if they have been invited by the lobby owner.
They can also leave the lobby at any time. Non-owners can search for public lobbies and join them.

## Start Match

Once the lobby is full and all members are ready, the lobby owner can start a match by calling the `StartMatch` API.
This will create a match and allocate the lobby members to the match. The allocation target can be specified in
the `StartMatch` API and can be one of the following: 'relay' or 'fleet'.

### Auto starting a match

The `StartMatch` API has a `start_at` field that can be set to a future UTC time. The match will be created at the specified time.

### Allocation Targets
#### Relay
For the 'relay' allocation target, the match will be created on the relay service specified by the `region` in the
 `StartMatch` request.

 #### Fleet
 For the 'fleet' allocation target, the match will be created on the fleet service specified by the `region` in the
 `StartMatch` request.


### Match Metadata

Each Lobby has a **metadata** property that can store an arbitrary JSON object. The lobby owner is able to update
the **metadata** of the party.

### Member metadata
Further, each lobby member also has a **metadata** JSON object that can be defined when the player joins the party.


### Fleet Metadata

The Lobby itself has an `allocation_metadata` field that can be set during Lobby creation or Lobby modification.
This field is a map of string to string (`map<string, string>`) and will be passed to the gameserver when the
match is allocated.
