# Inventory

Inventory snap allows you to setup your games or apps catalog items, containers, drop tables and loot boxes.
In addition, you can manage your app's virtual currency wallet using this snap.

## Summary

Here is a high level summary of the concepts in the Inventory snap.

1. Catalog: This is a catalog of your in-app items. This Snap supports different type of items such as consumables, stackables, purchasable etc.
2. Containers: These are groups of catalog items, virtual currencies, drop tables and trackables. Containers can be opened by the player to get the items inside. Containers also support locking and unlocking.
3. Currencies: These are all your in-app currencies. You can define currencies of different types, such as coins, gems, etc.
4. Drop Tables: Drop tables or loot tables essentially consists of items with various drop probabilities. Drop tables are delivered to the users inventory via a container.
5. Discounts: You can create discounts with specific eligibility criteria and apply them to the purchase price or unlock cost of items and containers.

### Catalog Items

The catalog is where you define your app or game inventory. Each item in the catalog has a name and various categorization options like class names, tags, and metadata
for ease of filtering and searching. Catalog items should have a specific consumption type, such as durable and consumable.
Further, consumable items can be stackable or non-stackable. Stackable items are items that can be stacked together in a single slot in the inventory.
Each item can either be purchasable or non-purchasable. Purchasable items can be bought by the player using virtual currencies.
You can also add a TTL (Time to Live) to the item, which will automatically remove the item from the user's inventory after the TTL expires.

#### Sub-inventory items
You can now create catalog items that are designated as "Sub-Inventories". Think of sub-inventory items as bags or pouches. They have certain rules:
    - They can not be nested
    - They can not be updated after that fact - you can not turn an existing item into a sub-inventory or visa versa.
    - They can't be marked as consumable, stackable, or as a container
		- Deleting a sub-inventory will "unnest" it's contents into the main inventory
- The Inventory snap provides the `MoveItemsToSubInventory` API to help you move user items into or out of sub-inventories.


### Containers
Containers are items that can contain other items, drop tables, virtual currencies or even trackables like XP and energy.
Like inventory items,  containers actually occupy an inventory slot. Containers can be opened by the
player to get the items inside. Containers can have a cost to unlock, which can be a combination of
virtual currencies, items, or trackables. Containers can have a TTL (Time to Live) which will automatically remove the container from the user's
inventory after the TTL expires.

#### Container phases
Every container has the following phases.
1. **Grant** - A container is granted to the user and it occupies an inventory slot.
2. **Unlock** - (optional) A container is unlocked by the user and the items inside the container are exposed but not yet committed to the user's inventory. This allows for the user to re-roll the items inside the container.
3. **Open** - A container is opened by the user, the grants are added to the users inventory and the container is removed from the user's inventory.

### Currencies

Currencies power your in game or app's economy. Currency can be used to purchase items, or can be awarded to the user.
A game or app can have more than one currency.

<Note>
If you have the analytics snap, Snapser automatically tracks your entire economy. So at any point,
you will see the exact state of your economy in real-time.
</Note>

### Currency Conversion

You can setup the conversion rates between your currencies. For example, you can define that 100 coins can be converted to 1 gem.

### Drop Tables
Drop tables are a way to grant mystery items to the player. Drops in a drop table can be one of:
1. **Items** - Non-container items.
2. **Currencies** - Virtual currencies.
3. **XP** - XP points from the Trackables snap.
4. **Energy** - Energy points from the Trackables snap.
5. **Drop Tables** - Other drop tables, enabling nested reward structures (version 1.8+). The maximum nesting depth is 10.
6. **Empty (No Reward)** - A drop that grants nothing (version 1.11+). Use this to give players a weighted chance of receiving no reward when the drop table is evaluated. An empty drop only takes a weight and cannot be combined with other rewards in the same drop, though it can sit alongside reward drops as one of the `OR` entries.

A drop table can be configured to have a combination of many drops, using `AND and ORs`during setup.
Each drop takes in:
1. **Item** - The item to be dropped.
2. **Min** - The minimum number of items to be dropped.
3. **Max** - The maximum number of items to be dropped.
4. **Multiple** - The total quantity of items to be dropped at once.
5. **Weight** - The weight of the item. The drop rate of the item is calculated as the weight of the item divided by the sum of the weights of all items in the drop table.

#### Drop tables and Containers
It should be noted that you cannot grant a drop table directly to the user.
Drop tables are consumed by your app's user via a container. Say, you create a container which ,
has a drop table. When the game client Grants and or Unlocks the container the contents of the drop
table are evaluated according to the drop rates.

#### Drop Index
API responses that evaluate or grant a drop table (such as `InventoryEvaluateDropTable` and `InventoryGrantDropTable`) include a `drop_index` field. The drops in a drop table form an array, and `drop_index` is the zero-based index of the drop that was selected during evaluation.

For example, given a drop table defined as:

```json
{
  "name": "treasure-chest",
  "drops": [
    { "weight": 60, "currencies": { "gold": { "min": 100, "max": 100, "multiple": 1 } } },
    { "weight": 35, "items": { "health-potion": { "min": 1, "max": 1, "multiple": 1 } } },
    { "weight": 5, "empty": true }
  ]
}
```

a `drop_index` of `0` means the gold drop was selected, `1` the health potion, and `2` the empty drop.

Since the granted rewards are already part of the response, `drop_index` matters when knowing *which* drop fired is not derivable from the rewards alone — for example, when two different drops grant the same reward (say, 100 gold with different presentation), or when an empty drop was selected and you want to show the right "better luck next time" treatment. To make use of it, your client needs access to the original drop table definition, which you can fetch via `InventoryGetDropTableContents`.

<Note>
  The top-level `drop_index` in the `InventoryGrantDropTable` response is deprecated. Use `grant_results.drop_index` instead.
</Note>

## Default User Inventory

You can setup the default Inventory items and currencies for a user by using the **Default Items** tool under the **User Tools** section.
You can also set Inventory items and currencies to start from zero.

<Note>
  Note only non-stackable inventory items can have a default quantity of 0. For
  stackable items the value has to be greater than 0.
</Note>

### Websocket Emitters

When [Web sockets](/docs/infra/snaps/hermes) are enabled on your snapends gateway, and you
have added the [Event Bus](/docs/infra/snaps/eventbus) snap, this snap can broadcast specific events related to inventory
changes directly to the app clients. These events are targeted to the appropriate user.
Each event is uniquely identified by an enum, and the event payload is a well-structured
protobuf message. These protobuf messages can be downloaded from the Downloads page.

You can choose to enable/disable events from the [Event Bus](/docs/infra/snaps/eventbus) configuration tool.

<div className="apisTable">
| Event Id | Event Name                         | Description                                            | Payload Proto Message                |
| -------- | ---------------------------------- | ------------------------------------------------------ | ------------------------------------ |
| 1        | INVENTORY_ITEM_ADDED               | Published when an item is added to user inventory      | EventInventoryItemAdded              |
| 2        | INVENTORY_ITEM_CONSUMED            | Published when an item is consumed                     | EventInventoryItemConsumed           |
| 3        | INVENTORY_ITEM_PURCHASED           | Published when user purchases an item                  | EventInventoryItemPurchased          |
| 4        | INVENTORY_CURRENCY_BALANCE_UPDATED | Published when user's virtual currency balance changes | EventInventoryCurrencyBalanceUpdated |
</div>
