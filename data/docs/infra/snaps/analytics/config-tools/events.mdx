# Events
This tool is used to view and add custom events to track, query and analyze application activity. Every event you create in this tool, creates a SQL table in your Analytics data warehouse. Each property you create in this tool, will be a column in that SQL table.

To get started:
1. Click on Events from the side Nav and then click on the **Add an analytics event** button.
2. This will open up a form where you can add a new event.

## Adding Custom Events

1. Select the `type,` which is either user in case you are going to fire this event from the client or app if you are going to fire an analytics call for your app in general which is not associated with any user
2. Add a custom event name, which can be any alphanumeric string
3. Select a sample rate. Use a sample rate of 100 if you want no sampling. Use a sample rate of 0 to not track any events.
4. You can choose to add custom properties for this event. E.g., let's say we create an event called `view` and have properties
   `category_one` and `category_two.` Then you will be able to fire off an event like.

```
{
  "view": {"category_one": "page", "category_two": "login"}
}
```

## Event Details
- **Type** - The type of event. Can be either user or app. User events can be used to track user activity in your app and requires user authentication. App events are used to track app-wide activity and do not require user authentication.
- **Name** - The name of the event. This can be any alphanumeric string.
- **Sample Rate** - The controls the sample rate of the event. Use this value to control how much data you feel is necessary to perform your business intelligence with. Some very high frequency events need not have every event stored. This can be a performance optimizer and importantly a money saver. Use a sample rate of 100 if you want no sampling. Use a sample rate of 0 to not track any events.

## Properties
- You can add upto 12 properties for each event. Each property can be of type string, number, or timestamp.
- Each event has the following properties by default:
  - **user_id** - The user id of the user who fired the event
  - **session_id** - The session id of the user who fired the event
  - **created_at** - The time the event was fired
