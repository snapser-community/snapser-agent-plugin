# Analytics

Every modern application needs analytics. Analyzing various aspects of your app gives you the insights you need to improve it.  Even simply just snapping the Analytics Snap gives specific metrics like DAU, MAU, etc., for free, out of the box without having to make explicit calls from your client. This simple yet powerful tool should be an essential Snap for every application, game or digital experience.

## Analytics Events
You can think of an analytics event as a table in the data warehouse where each property is a column. Every analytic events can have upto 12 properties. This snaps come with out of the box built-in events. You can also add your own custom events via the Snaps admin tool. The snap ensures the incoming request adheres to the event and its properties and forwards the data to a Data warehouse. Developers then have access to this Data warehouse where they can run ad-hoc queries, create charts and dashboards.

## Default Events
Snapser offers built-in events as part of the Analytics snap. Some of the events are automatically populated by other snaps viz. **Snap Event Tables** and some have been created by Snapser for you to leverage viz. **Pre-built Event Tables**.

### Snap Event Tables
<Note>
	These tables get automatically populated by other snaps like Auth, Experiments, Inventory, IAP,	and Statistics. You can directly query these tables using the Olympus tool, to get insights into your application.
</Note>

1. **Logins**: Tracks user logins. This event is automatically populated by the [Auth Snap](/docs/infra/snaps/auth).
1. **Installs**: Tracks app or game installs. This event is automatically populated by the [Auth Snap](/docs/infra/snaps/auth).
1. **Experiments**: Tracks your app experiments. This event is automatically populated by the [Experiments Snap](/docs/infra/snaps/experiments).
1. **Segments**: Tracks live user segments. This event is automatically populated by the [Statistics Snap](/docs/infra/snaps/statistics).
1. **Payments**: Tracks virtual currency in your game or gamifieid app. This event is automatically populated by the [Inventory Snap](/docs/infra/snaps/inventory).
1. **Economy**: Tracks your application or game economy. This event is automatically populated by the [Inventory Snap](/docs/infra/snaps/inventory).
1. **IAP Purchases**: - Tracks your IAP purchases. This event is automatically populated by the [IAP Snap](/docs/infra/snaps/iap).

### Pre-built Event Tables
<Note>
	These tables are created by Snapser for your convenience. It is the responsibility of the developer	to populate these tables by firing `Analytics.UserEvent` or `Analytics.AppEvent` calls from the client.

	If you want a slightly different way for tracking sessions, ads, errors or milestones, you can always	ignore these default ones and create your own custom event tables.
</Note>

1. **Sessions** - Track user sessions in your application.
1. **Advertisements** - Track your ad impressions, clicks, and conversions.
1. **Errors** - Track errors in your application.
1. **Milestones** - Track user milestones / funnels in your application.

<Note>
	It should be noted that Snapser provides the following properties with these pre-build events for free.
	So you do not need to add them explicitly:
	- **user_id** - The user id of the user who fired the event
	- **session_id** - The session id of the user who fired the event
	- **created_at** - The time the event was fired
</Note>

#### Milestone and Funnel Tracking
Milestone or funnel tracking is a useful tool to determine drop-offs in your app. These can be drop offs during your FTUE/NUX or during a feature. Snapser provides you with a Milestones table that has properties like: milestone_name, milestone_step etc. Using this information you can easily identify the drop offs rates.

Example: Say a game's first time user experience, has three major things that the user needs to do before they can start playing the game. Every time a user completes one of the steps, the game client will fire off an analytics call passing the appropriate step number. Using, the Snapser Business Intelligence Querying tool, a game studio will be able to figure out, the number of people completing step 1, 2 and 3. If users know that they have a 90% completion rate on Step 1 but only 20% completion rate on Step 3, it would tell them that their FTUE is too long or has an issue.


## Custom Events
Custom events give a way to your product or data analyst team to come up with their own
taxonomy to track in-app activity. You can add custom events via the Snaps admin tool. Each event can have a type and a sample rate. The type can be either user or app. You should use the type user if you are going to fire this event from the client. Use the type app if you are going to fire an analytics call for your game in general which is not associated with any user or from your game server. Each even can have upto 12 properties to each event. Each property can be of type string, number, or timestamp.
Snapser also provides properties with every event for free:
- **user_id** - The user id of the user who fired the event
- **session_id** - The session id of the user who fired the event
- **created_at** - The time the event was fired

## Query your Data Warehouse

### Business Intelligence Tool

Once you have added either a user or an app event, your team can start querying your data warehouse. You can use the **Business Intelligence** tool to run queries against your data
warehouse.

1. Click on Events tool from the side Nav and then on the **Business Intelligence** button.
1. This will open up the Snapser Business Intelligence tool.
1. Select the **SQL Editor** tab and click on **SQL Lab**.
1. In the first drop down pick the data warehouse name - this name will be prefixed with your `snapend name`.
1. Next, select `public` for `Schema`.
1. Finally you can select the table name from the last drop down.
	 ![Olympus Sql](/images/docs/olympus-sql.png)
1. Let's say you had added a user event called view with a property
   **category_one** . Snapser creates a table using the event_type and event_name viz. user_view where
   user is the event type and view is the event name. All the properties become columns of that table.
1. Using the example above you can execute a query like:

    ```
      select category_one from user_view;
    ```
1. Click `Run` Query to see the results.

## Batching Events

The analytics snap supports batch event uploads. Using the batch API your client can cache 100 events and send them once. The client can add a timestamp with every entry in the batch. If the client does not do this, then the Analytics snap adds the timestamp of when the payload was received. The client can also provide a time_offset so as to make sure data entering your data warehouse is in the timezone your team is in. Without this override, all the data stored in the data warehouse is in the Pacific Timezone.

## Deleting Events
Snapser does not allow you to delete any of the Pre-built tables. However, custom event tables created by a developers, can be deleted. It should be noted that, in case the deletion was un-intentional and to prevent any permanent data loss, Snapser does a soft delete of your table and it will be available for 7 days.  After 7 days, the deleted custom event tables will be permanently deleted.
