# Quests

Quest snap allows you to add quests or missions to your game.

## Concept

1. A quest contains tasks. Completion of all the tasks in the quests completes a quest.
2. Every task in a quest has a goal. The task is considered complete once the user reaches the goal. Rewards can be set for completing a task.
3. Additionally, you can also setup rewards for completing the entire quest. Rewards can be an inventory item, currency, statistic or a trackable.

## Audience

Quests can be made available to all users or to a specific segment of users. If
you want to restrict quests to a specific segment, you will need the
Segmentation snap.

## Period

The setup for recurring and non recurring quests is done via a cron
expression.

1. For recurring quests, the quest starts at the first tick after the creation. For example, `* */2 * * *`
   evaluates to quest that repeats every 2 minutes. If the quest was created at 1:00, the quest will start at 1:02.
2. For non recurring quests, this expression is just for starting the quest.


## Tasks and Goals

Every quest can have multiple tasks. Each task has a goal that needs to be
achieved to complete the task. The goal can be one of the following types:

- **Counter**: This is a goal counter that is tracked by the snap. The goal can be positive or negative.
  This goal is always an absolute count.

- **Item**: This tracks an item from inventory. The count can be absolute or relative to the number when the quest starts for the user. An example of such a task can be "Acquire 10 swords". Now, whenever "swords" are granted to the user, the progress of the task is automatically updated.

- **Currency**: This tracks a currency from inventory. The count can be absolute or relative to the number when the quest starts for the user.  An example of such a task can be "Acquire 10 gold". Now, whenever "gold" is granted to the user, the progress of the task is automatically updated.

- **Statistic**: This tracks a `counter` statistic from the Statistics snap. The count can be absolute or relative to the number when the quest starts for the user.  An example of such a task can be "Deal 10,000 damage". Now, whenever the relevant statistic is updated for the user, the progress of the task is automatically updated.

- **Trackable**: This tracks XP or energy from the Trackables snap. The count can be absolute or relative to the number when the quest starts for a user. An example of such a task can be "Reach 200 XP". Now, whenever the user reaches "200 XP", this task will be marked as complete.

<Note>
The Item, Currency, Statistic and Trackable tasks need the Inventory, Statistics and Trackables snaps respectively,
to be part of your snapend. Also, a quest is only marked as completed if all the tasks are completed.
</Note>

## Rewards

Rewards can be added to a particular task or the entire quest. Rewards are granted when the task or the quest is completed.

The Quest Snap supports four types of rewards: Catalog Item, Currency,
Statistic, and Trackable (XP or Energy).

- **Catalog Item**: You can set up the count of a particular catalog item to be granted as a reward for completing the quest.
  Note: Inventory snap is required for this.

- **Currency**: You can set up the count of a particular catalog item to be granted as a reward for completing the quest.
  Note: Inventory snap is required for this.

- **Statistic**: You can set up the count of a particular statistic item to be granted as a reward for completing the quest.
  Note: Statistic snap is required for this, and only counter-type statistics are supported.

- **Trackable**: You can set up the count of a particular trackable item viz. XP or Energy to be granted as a reward for completing the quest.
  Note: Trackable snap is required for this.

<Note>
  You need the Inventory, Statistics or Trackable snaps to be part of your snapend to use
  the rewards feature.
</Note>

### Claiming Rewards
To claim rewards for a quest task, invoke the `ClaimTaskRewards` endpoint. Rewards for a task can only be claimed once.
To claim rewards on completion of a quest, invoke the `ClaimRewardsForQuest` endpoint. For quests of recurring type, you can only claim rewards for the quest before the next refresh.
Once the quest refreshes, rewards for a quest completed earlier cannot be claimed.

## Quest Assignment

Quests can either be manually assigned to users or auto assigned. For auto
assigned quests, the quests get assigned dynamically at runtime when the game code invokes
GetActiveQuests.

<Note>
  For auto-assigned quests, we recommend calling GetActiveQuests during game startup to directly assign
  the available and active quests to users. This api call assigns any available
  quests to the user, and also refreshes the progress if needed for a recurring
  type of quest.
</Note>

### Websocket Events emitted by snap

When [Web sockets](/docs/infra/snaps/hermes) are enabled on your snapends gateway, this snap can broadcast specific events related to quest changes directly to the game clients. These events are targeted to the appropriate user. Each event is uniquely identified by an enum, and the event payload is a well-structured protobuf message.
These protobuf messages can be downloaded from the Downloads page.

You can choose to enable/disable events from the `Emitters` tab in Quests Admin tool.

| Event Id | Event Name             | Description                                               | Payload Message           |
| -------- | ---------------------- | --------------------------------------------------------- | ------------------------- |
| 1        | QUEST_ASSIGNED         | Published when a quest is assigned to the user            | EventQuestAssigned        |
| 2        | QUEST_PROGRESS_UPDATED | Published when progress of any task in a quest is updated | EventQuestProgressUpdated |
| 3        | QUEST_REWARD_CLAIMED   | Published when rewards for a quest are claimed            | EventQuestRewardClaimed   |
