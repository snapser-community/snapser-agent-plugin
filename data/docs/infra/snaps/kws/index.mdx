# Kids Web Service (KWS)

Epic Games and Snapser have partnered together to enables game studios to have a fully COPPA compliant backend for their games.

<Warning>
  This is a Premium snap. You will need to be on a Premium plan to use it.
</Warning>

## About KWS
The Kids Web Service (KWS) is a service that helps game developers comply with the Children's Online Privacy Protection Act (COPPA) by providing age-gating and parental consent features. The KWS Snap provides a seamless integration between your Snapend and the KWS service, allowing you to easily configure and manage your COPPA compliance settings.

<Note>
  Presently, the Kids Web Service, does not have a self service portal. You need to reach out to their team to get the necessary credentials.
</Note>

## Concept
When it comes to COPPA compliance, there are two key concepts to understand:
1. Parental Consent: Before a child can access your game or a subset of game features, you must obtain verifiable parental consent. This can be done through a variety of methods, such as email verification, credit card verification, or a signed consent form.
   This part is completely handled by the KWS service. The game client directly interacts with the KWS service to get the parental consent kicked off.
2. Server Gating: This is where Snapser comes in. The KWS Snap provides a permission harness that allows you to gate access to your game and its features based on the age of the player and the consent of the parent or guardian.

### Flow Diagram
The flow diagram below illustrates how the KWS Snap integrates with the KWS service to provide age-gating and parental consent features.

![kws-flow](/images/docs/kws-flow.png)

1. The game client authenticates with the Auth snap and gets a Snapser session token.
2. The game client sends a request to the GetUserSettingValues API in the KWS snap to get the user specific settings.
3. The KWS snap sends a request to the KWS service to get the user specific settings.
4. The KWS service returns the user specific settings to the KWS snap, which it caches for faster access. This data is then returned back to the game client.
5. Now, say the game client figures out that the user is a child and needs parental consent for a particular feature. The game client sends a request to the KWS snap to get the parental consent.
6. The KWS snap sends a request to the KWS service to get the parental consent. The KWS service then sends an email to the parent or guardian with a link to provide consent.
7. Once the parent or guardian provides consent, the KWS service makes an API call to the KWS snap to update the user specific settings.
8. The KWS Snap updates the user specific settings. The client is expected to poll for new permissions or if using Snapser web sockets will get the updated permissions in real time.

## Example Use Case
Imagine you are developing a game that is targeted at children under the age of 13. To comply with COPPA regulations, you need to ensure that you obtain verifiable parental consent before allowing children to access chat in your game. However, if a child is above 16 years of age, you can allow them to access chat without parental consent.
As a game studio you will need to:
1. Set up the KWS service with your Snapend.
2. Create a permission in the KWS console that checks the age of the player and whether they have parental consent to access chat.
3. Add the permission to the KWS Snap on Snapser and attach it to the chat API in your game.

## Snaps integration
The KWS Snap integrates with all the Snaps on Snapser. It provides a permission harness that allows you to gate access to your game based on the age of the player and the consent of the parent or guardian.

in the left nav bar, click on `Tools > API Explorer` and then select the snap name to view the APIs.

### Websocket Emitters

When [Web sockets](/docs/infra/snaps/hermes) are enabled on your snapends gateway,
and you have added the [Event Bus](/docs/infra/snaps/eventbus) snap, this snap can broadcast
specific events related to KWS value changes directly to the game clients. These events are
targeted to the appropriate user. Each event is uniquely identified by an enum, and the event
payload is a well-structured protobuf message. These protobuf messages can be downloaded from
the Downloads page.

You can choose to enable/disable events from the [Event Bus](/docs/infra/snaps/eventbus) configuration tool.

| Event Id | Event Name                   | Description                                                     | Payload Proto Message         |
| -------- | ---------------------------- | --------------------------------------------------------------- | ----------------------------- |
| 1        | KWS_EFFECTIVE_VALUES_CHANGED | Published When Kws Effective Values Changed Webhook Is Received | EventKwsEffectiveValueChanged |
