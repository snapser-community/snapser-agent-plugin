# Profiles

The Profile snap allows games and apps to set up profiles for their user
base. Developers can configure profile attributes and set them up to be unique or searchable.
Each profile attribute also comes with built-in access control.

Plenty of games and apps develop a structure for a user profile and end up storing the
data in a service like **storage**. While you
can certainly go down that route, any updates to the profile properties become
a nightmare to manage. The profile service makes all this a breeze for dev
teams. You can set up user profile properties in your admin tool and have
granular access control for every property you have added.

## Unique and Searchability

You can configure your profile attributes to be unique and or searchable. Unique attributes are
guaranteed to be unique across your entire user base. Searchable attributes allow you to use
the `ProfileSearch` API to search users based on the attribute. It should be noted that, unique
attributes are by default searchable. On the other hand, if you can also configure an attribute
to be non-unique and non-searchable. Profile snap stores these attributes and makes them
available for standard retrieval.

<Note>
  [IMPORTANT]: You can have a maximum of 10 unique attributes and 10 purely
  searchable attributes.
</Note>

## Access Control

To understand access control, let's take an example. Say for the app or game you are
building, you want to store a user profile with the following properties: **gamer tag**, their **first name**, and their **last name**. Also you decide that you do not want to
expose the last name of users to anyone other than the owner. Therefore, you can
set up **last name** in the admin tool as a private property. This ensures that only the owner can see the entry
for the last name when visiting their profile. If another user visits the owner's profile, the **last name**
will automatically be hidden.

### Access Types

There are some profile attributes that need to be private to a user. For example,
most developers chose to take the last name as an input from the user during profile creation, \
but not actually show the last name to other users in the app. Configuring an attribute to be `private`
ensures that only the owner of the profile is able to retrieve that attribute. No one else sees a users
private attribute.

## Upcoming enhancements

### File-based attributes

We plan to expose a file based attribute. As an example, once we support this
attribute, you can get your app client to upload a user profile picture.

### Custom access type

We want to integrate this service with the Social graph Snap. Allowing you to
set access for a particular attribute based on user relationships.
