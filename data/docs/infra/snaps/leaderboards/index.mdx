# Leaderboards

The Leaderboard snap makes it easy to add a sense of competition to your game or even social app.
At the core this snap keeps score for your entire audience at a global or per
league level, including player ranks. The service is extremely comprehensive
and supports both recurring and non-recurring as well as tiered and
non-tiered leaderboards.

## Leaderboard Types

There are mainly two types of leaderboards

1. **Global**: Single leaderboard for your entire user base.
2. **Tiered**: Leaderboards with tiers and each tier having a fixed bucket size. These leaderboards are used to create tiers within your game or app.

<Note>
  If you are creating a mass market game or have the ambition to do so, we
  recommend always choosing a tiered leaderboard. This will allow you to create
  tiers or leagues within your game and give your users a sense of competition that feels
  fair.
</Note>

### Global Leaderboards

Global leaderboards are the simplest form of leaderboards. Every user in your
game is ranked against every other user. This is the most common form of
leaderboard. However it's not the most engaging form of leaderboard. This is
because most users will see their rank as a very large number and not feel
compelled to improve it.

<Note>
You should consider using a tiered leaderboard if you want to create a sense of
competition within your game.
</Note>

### Tiered Leaderboards

One major problem when you use a global leaderboard is that it's hard to
ignite a sense of competition for most of your users. For example if a user
sees that their rank is 1,000,000 they wont feel compelled to improve their
rank. Tiered leaderboards solve this problem by creating tiers within your
game. Each tier has a fixed bucket size and users are ranked within their
bucket. Now, instead of competing against the entire game user base, users of a
tiered leaderboard are competing only with a limited set. This makes the
competition feel fair.

#### Example of a Tiered Leaderboard Setup

Best way to think about tiered leaderboards is in the form of a league.
In the leaderboards Snap you create 3 tiers. One Bronze tier with a bucket size of 200,
then a silver tier with a bucket size of 100 and a gold tier with a bucket size of 50.
Note there can be any number of buckets within each tier and this is completely managed by the snap.
Users typically start in the Bronze tier and compete against the other 200 people. At the end of the league period,
the top X players can be promoted to the next league. The bottom Y people get moved down to the previous league. The
promotion and demotion is totally up to the game team.

## Recurring and Non-Recurring

Recurring leaderboards get reset over a schedule automatically. Non-recurring
leaderboards are forever leaderboards where the scores never reset.

<Note>
  When using a recurring leaderboard, the service supports the client querying
  for their score from the previous phase. This is useful if you want to look at
  a user's rank in the previous event and decide whether to give them a winning
  prize.
</Note>

## Retrieving Leaderboard Data

Every leaderboard can be set up to return user ranks in an **Ascending** order or **Descending** order.

## Handling Rewards
Say you have a tiered leaderboard with 3 tiers. You have decided that the top 3 ranks get a special reward. Most game studios,
handle this directly client side, for a client authoritative game. Server authoritative games handle this via a BYOSnap.
In both cases, the code detects that a rollover has happened recently and queries the leaderboard service to get the rank,
of the previous period. If the user is within the top three ranks a prize can be granted to the user.

<Note>
The Leaderboards Snap does not do any kind of automatic granting of prizes. This is left to the game team to handle.
</Note>

## Handling Cheaters

Leaderboards are always prey to cheaters, especially if your league has some sort of a reward associated with it.
There is a super simple trick that some game studios use. They create a `_c` version of the leaderboard via the Leaderboards
snaps admin. The setup is identical to the main leaderboard for your game. However, whenever your game detects a cheater, you
should throw the user to this new leaderboard. This way slowly but surely all cheaters start playing against each other and
the main leaderboard stays clean.

<Note>
This is just one of the many simple hacks typical game studios use. The Leaderboards Snap does not do any kind of automatic
cheater detection. This is left to the game team to handle.
</Note>

## APIs

The `Leaderboards` snap exposes the following APIs

<div className="apisTable">
| API Name            | HTTP Method | API Description                                                                               |
| ------------------- | ----------- | --------------------------------------------------------------------------------------------- |
| [LeaderboardsGetScores](#leaderboardsgetscores-api)           | GET         | Gets the standings within a leaderboard                                                       |
| [LeaderboardsIncrementScore](#leaderboardsincrementscore-api)      | PATCH       | Increments the score on the leaderboard                                                       |
| [LeaderboardsSetScore](#leaderboardssetscore-api)            | PUT         | Updates the score on the leaderboard for the logged in user (only non 'counter' leaderboards) |
| [LeaderboardsBatchGetScores](#leaderboardsbatchgetscores-api)       | GET         | Gets the standings within a leaderboard for multiple users |
| [LeaderboardsBatchIncrementScore](#leaderboardsbatchincrementscore-api) | PATCH       | Increments the scores on the leaderboard                                                      |
| [LeaderboardsBatchSetScore](#leaderboardsbatchsetscore-api)       | PUT         | Updates the score on the leaderboard for the logged in user (only non 'counter' leaderboards) |
</div>
