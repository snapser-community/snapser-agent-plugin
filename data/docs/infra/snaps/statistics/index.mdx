# Statistics and Segmentation

The Statistics and Segmentation snap is two services clubbed into one. The
statistics part of the service allows game and app dev teams to set up real-time
statistics for their user base that they can quickly increment and update from
the client code. Using segmentation, they can create user cohorts based on
their statistics. Segmentation enables games and apps to give their users a unique
experience by combining others snaps like Remote Config and Experiments.

<Note>
  The Statistics snap should not be confused with the Analytics service. For example, in a traditional game use case, the
  user statistics service is used to store game stats for a user, whereas,
  Analytics is mainly for game-level analysis.
</Note>

## Quick Tour
<Video src="https://www.youtube.com/embed/8rPGyEN_ddY" title="Snapser - Statistics and Segmentation Snap" />

## Statistics

A Statistic is a unique metric that you want to store for every user. Each
user can have a stat incremented. The segmentation part of this Snap uses
these user statistics to create user cohorts.

### Statistic Types

Currently, there are three types of statistics:

1. **Counter**: number that can be set or incremented.
2. **Timestamp**: Unix timestamp.
3. **String**: any string.

### Statistic Scope

The scope describes the access level of the statistic. There are two types of scopes:

1. **External**: App clients, cluster services, and servers having the snapend API key can modify these stats.
2. **Internal**: Only other snaps within your cluster can modify these stats. This is to prevent cheating. These stats can be updated using app auth as well.

## Segments

Segments are cohorts of the game or app user population based on user statistics. Users will enter or exit segments as their specific user stat increases or decreases.

### Predicates
Segments are setup as a combination of predicates. Predicates are rules that are evaluated against the user statistics. Segments can have multiple predicates and can be inclusive or exclusive.

#### Predicate Example
For example, a game may want to target and reward players logged in 1000 times. To handle this, you can create a statistic for "logins" in the admin tool and a segment with the rule: logins ≥ 1000. Once you setup this rule, when a players "login" stat reaches 1000, they automatically "enter" the segment. Using other snaps like remote config and or experiments you can now update your game experience for the user. Also you may now trigger an action to grant the user an achievement and reward them some currency on entering the segment.

<Note>
  Presently, you can have 20 predicates per segment.
</Note>

## Snap Integrations
The Statistics and Segments you create with this snap can be used with other snaps like Events, Experiments, Inventory, Notifications, Remote Config, and Trackables.
This allows you to create a unique app experience for your users based on their statistics and segments.

### Analytics on Segments
Additionally, if you have the analytics snap as part of your snapend, this snap automatically forwards the
segmentation data to the analytics snap. This allows you to analyze the user segments in the analytics tool
in real-time. The table that is created in the analytics tool is named `user_snap_segments`.

## APIs & Emitters

The `Statistics & Segmentation` snap exposes the following APIs

<div className="apisTable">
| API Name                  | HTTP Method | API Description                                           |
| ------------------------- | ----------- | --------------------------------------------------------- |
| [StatisticsIsUserInSegment](#statisticsisuserinsegment-api)           | GET         | Returns true/false if user is in segment or not           |
| [StatisticsGetUserStatistics](#statisticsgetuserstatistics-api)         | GET         | Fetches all user-statistics for user or stat              |
| [StatisticsGetUserStatistic](#statisticsgetuserstatistic-api)          | GET         | Fetches a specific user statistic by user id and stat key |
| [StatisticsIncrementUserStatistic](#statisticsincrementuserstatistic-api)    | PATCH       | Increments a user-statistic                               |
| [StatisticsBatchUpdateUserStatistics](#statisticsbatchupdateuserstatistics-api) | PUT         | Increments user statistics in bulk                           |
| [StatisticsSetUserStatistic](#statisticssetuserstatistic-api)          | PUT         | Sets a user statistic to exact value provided             |
| [StatisticsBatchSetUserStatistics](#statisticsbatchsetuserstatistics-api)          | PUT         | Sets user statistics in bulk for multiple users             |
| [StatisticsBatchGetUserStatistics](#statisticsbatchgetuserstatistics-api)          | GET         | Fetches all user-statistics for multiple users             |
</div>

### Websocket Events emitted by snap

When [Web sockets](/docs/infra/snaps/hermes) are enabled on your snapends gateway, this snap can broadcast specific events related to statistics changes directly to the app clients.
These events are targeted to the appropriate user. Each event is uniquely identified by an enum, and the event payload is a well-structured protobuf message.
These protobuf messages can be downloaded from the Downloads page.

You can choose to enable/disable events from the `Emitters` tab in Statistics Admin tool.

| Event Id | Event Name                 | Description                                  | Payload Message               |
| -------- | -------------------------- | -------------------------------------------- | ----------------------------- |
| 1        | STATISTICS_UPDATED         | Published when a user's statistic is updated | EventStatisticsUpdated        |
| 2        | STATISTICS_SEGMENT_UPDATED | Published when a user's segment changes      | EventStatisticsSegmentUpdated |
